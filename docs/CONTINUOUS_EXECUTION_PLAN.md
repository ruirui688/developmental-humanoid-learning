# CPU 发育式学习：持续执行目标与阶段账本

> 2026-10-11；用户要求把项目作为持续目标执行，完成单次实验或提交后继续推进下一项。

## 1. 当前持续目标

在现有 CPU 和少量在线辨识条件下，建立可审计的低维多关节闭环验证：机器人通过自身动作与原生感觉形成局部身体模型，模型改善控制，并检验未知动力学变化与能力门控的收益。所有先验、失败版本、交互、计算和风险指标均公开。

本机先做到低维机制验证；之后的完整翻身、起身、站立、行走及 G1/真机是长期路线，需要对应资源与安全验收。当前不以一个肩关节的成功宣布整个项目目标完成。

已经完成的 [E1 v2](CPU_LOCAL_BODY_RESULTS.md)是起点：指定独立轨迹预测改善，单肩同 MPC 跟踪改善；闭环自身轨迹的预测退化、努力与动能升高仍未解决。

## 2. 执行方式

1. 选取当前最早未验收的阶段，先做最小实现或开发诊断。
2. 使用开发数据选择候选，记录所有候选及成本；正式协议、代码、阈值、种子与预算先冻结并提交。
3. 从干净源码执行 CPU 实验，保存真实交互与每次更新，不删除失败或补跑到成功。
4. 独立重算日志、检查信息隔离与原始清单，区分记录正确和科研结果通过。
5. 更新阶段账本、结果与失败解释，相关检查通过后正常提交、推送。
6. 接着执行下一个可推进的阶段。小里程碑、报告、提交或单个局部门通过都不自动结束持续目标。

如果候选失败，保留结果，针对明确原因修订新的开发版本；不能修改已有留出门或把同一留出重新当作未见数据。证据支持否定某个机制时也要如实结论，不以无限重复或改变任务换取漂亮结果。

用户明确暂停时暂停持续目标。需要 GPU、真机授权/现场条件或无法获得的外部资源时，记录具体依赖并继续独立 CPU 工作；不虚构完成、静默安装驱动或绕过安全层。

C2/C3 的正式矩阵根据 C1 的开发依据另写冻结协议。C4–C6 在实施前各自固定任务、基线、完成条件、停止条件、风险分母与预算；本文件是执行顺序，不代替实验预注册。

## 4. 目标完成条件

本持续目标的交付需要完成低维多关节的身体预测、闭环控制、变化适应和成熟机制对照，并具备以下证据：

- 真实刚体接触；模型只使用原生感觉与当前已知命令，底层保护独立。
- 至少两个关节与双关节局部任务；既有单肩结果单独报告。
- 同初始知识、相同权限/目标/场景下的冻结模型、学习模型和调优经典控制；单步与多步预测同时报告。
- 未见动力学变化中的冻结/适应对照，冷启动、变化适应与技能复用成本分开。
- 固定成熟与能力门控的公平对照，完成标准一致，风险/努力/交互和停滞均保留。
- 开发与正式留出分开；各阶段门在结果前冻结，模型选择不读取正式留出。
- 全部结果可从源码提交、配置、逐 seed 原始轨迹、参数/更新记录与清单复核；相关检查、普通提交与推送完成。

完成实验与证明优势是不同结论。如果强基线、消融或风险指标否定候选，必须公开；持续研究据此推进有依据的修订。不能仅因增加模块或留下文档就把整个目标标记完成，也不能用仿真结论替代真机验收。

## 5. 资源与信息边界

仅 CPU，允许少量 RLS/局部系统辨识；不运行大规模 PPO，不引入步态教师、预训练任务策略或外部任务动作。基线控制器、公开身体与限位、固定模型结构、任务目标和理想传感都属于需要披露的先验。

接触力、动能、真实参数等只作诊断；它们不能暗中进入部署模型。共同上限不代表相同实际努力；零停止不代表安全。原 E1 留出 seed 10/11/12 已使用，后续版本需要新的独立最终评估。
