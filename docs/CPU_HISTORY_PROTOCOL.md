# CPU 无训练指令历史与预测时域对照协议

本批在正式结果产生前冻结实验设计，沿用 [前一批失效边界实验](CPU_FAILURE_RESULTS.md) 的固定动力学、初态、目标与扰动，只增加显式指令历史预测和预测时域对照。只使用 CPU，不运行 PPO、监督拟合、RLS/ARX 或任何参数学习。模型、控制增益、声明延迟与控制权限在一次运行中保持固定。

这是一份仓库内的实验协议，不是外部平台注册。它检验已知初始延迟的处理与未知突变下的模型失配，不检验延迟辨识、身体模型学习、冷启动技能获得、G1 或真机能力。

## 1. 问题与因果边界

前一批中，30 步延迟超过原规划器的 20 步时域，且预测把新命令当作立即执行。因此，本批拆开两个因素：

1. 在相同预测时域下，使用自己已发出的指令历史与事先声明的初始延迟，是否改善预测和控制？
2. 在相同执行假设下，把时域从 20 步扩展至 50 步，会带来什么变化？
3. 初始延迟知识固定后，未告知控制器的延迟或增益突变，会否再次产生预测失配？

采用 `immediate/history × H20/H50` 的 2×2 对照，固定 PD 为独立参照。所有方法始终采用同一最高档权限，取消成熟与能力门控，避免权限和残差来源同时变化。原门控与持续失败退级变体保持原样，不在本批替换默认实现。

`history` 方法获得额外的、事先公开的初始延迟先验；它没有学得该延迟。`immediate` 方法作为执行假设消融忽略这条先验。相同动力学、目标和权限并不使两者的信息使用完全相同，因此结果须称为“已知初始延迟的历史建模诊断”，不能称为相同未知信息条件下的在线学习收益。

## 2. 固定配置

| 配置项 | 固定值 |
|---|---|
| 种子 | `10, 11, 12`；同种子各方法初态相同 |
| 每次运行 | 最多 450 次仿真推进，`dt = 0.02 s`，最长 9 s |
| 初态 | 位置 `uniform(-0.005, 0.005)`、速度 `uniform(-0.003, 0.003)`，各两维；每次重建对应种子 |
| 固定目标 | `(0.08, -0.06) rad` |
| 权限 | 始终 `STAGES[2]`：两关节可控，命令限额 `(1.0, 1.0)` |
| 硬命令限额 | `(1.2, 1.2)`，不等同于未知增益下的物理力矩限制 |
| 状态退出 | 任一 `abs(q) > 0.35 rad`、`abs(v) > 1.2 rad/s` 或非有限状态 |
| 周期扰动 | 每 25 步的前 2 步，外部力矩 `(0.12, -0.10)`；其余零 |
| 突变 | 0-based `command_step = 225`，第 226 次 transition 开始采用新参数 |
| 预测时域 | `H20 = 20` 步、0.40 s；`H50 = 50` 步、1.00 s |
| 候选 | 每关节 7 个等距常值命令，两关节共 49 个候选 |
| 成本权重 | 位置/速度/努力/命令变化：`30.0/0.2/0.025/0.04` |
| 规划状态界限 | 位置 `0.30 rad`，速度 `1.15 rad/s` |
| 固定 PD | 名义弹簧和耦合前馈，`kp = 4.0`、`kd = 2.0` |
| 评估结构 | 单条连续轨迹；突变不重置状态、命令历史或上一步命令 |
| 学习与调参 | 模型、策略、增益、声明延迟、成本权重更新次数全部 0 |

名义身体模型保持 `JointParameters()`：惯量 `(0.8, 1.0)`、阻尼 `(1.1, 1.25)`、刚度 `(2.8, 3.2)`、执行器增益 `(1, 1)`、耦合 `0.15`。`FixedBodyModel` 本身仍预测一个给定实际作用命令的单步推进；延迟在它外面的历史包装中处理，不写入或更新动力学参数。

成本计算保持原定义：命令变化成本只在当前候选与上一步发出命令间计一次；各预测步累计状态与候选命令的努力成本。H50 增加了累计成本与内部计算量，因此不能把跨时域变化仅解释为“更多未来信息”。同一时域内的 `immediate/history` 比较是主要历史效应对照；跨时域比较属于这一完整规划配置的变化。

## 3. 场景、方法与预算

| 场景 | 实际初始参数 | step 225 起实际参数 | 控制器声明初始延迟 |
|---|---|---|---:|
| `nominal` | 名义 | 名义 | 0 |
| `constant_delay_6` | 延迟 6 步 | 不变 | 6 |
| `constant_delay_15` | 延迟 15 步 | 不变 | 15 |
| `constant_delay_30` | 延迟 30 步 | 不变 | 30 |
| `delay_jump_0_to_30_at225` | 延迟 0 步 | 延迟 30 步 | 0 |
| `delay_jump_15_to_30_at225` | 延迟 15 步 | 延迟 30 步 | 15 |
| `gain_drop_1_to_0.25_at225` | 名义 | 增益 `(0.25, 0.25)` | 0 |
| `gain_drop_1_to_0.125_at225` | 名义 | 增益 `(0.125, 0.125)` | 0 |

除表中字段外，所有实际参数保持名义值。声明延迟在构造控制器前由协议显式给定，不能从 `plant.parameters`、`scenario.parameters_at()` 或实际执行源索引中提取；参数突变时声明值仍保持不变。场景标识和突变时刻只供实验编排与事后计量，不作为策略输入。

每个场景和种子运行 `immediate_h20`、`history_h20`、`immediate_h50`、`history_h50` 与 `pd`，共 **8 × 3 × 5 = 120 次**，总交互上限 **54,000 步**。H50 在查看本批结果前固定，不根据结果继续延长时域。所有早停保留，不补种子、不补跑至成功，不从结果中剔除失配或时域不足组。

全权限时每次动作搜索分别推进 `49 × 20 = 980` 或 `49 × 50 = 2,450` 个内部模型状态；PD 不搜索候选。完整预算的规划内部状态推进上限为 **74,088,000** 次，即 `8 × 3 × 450 × (2 × 980 + 2 × 2450)`；另行计量单步残差预测，均与实际仿真交互分开报告。

## 4. 历史预测与严格信息边界

在控制步 `t` 开始时，策略可以访问 `state[t]`、固定目标、已发出的 `command[0:t]`、上一步发出命令、固定权限、名义动力学，以及协议声明的固定初始延迟 `d_declared`。它不能访问仿真器实际增益、惯量、实际延迟、执行命令、执行索引或未来状态。控制器不接受仿真器对象或动态场景参数。

对某个候选常值命令 `a`，`history` 组在预测步 `s = 0, ..., H-1` 选取名义作用命令：

```text
k = t + s - d_declared
k < 0       -> 零命令
0 <= k < t  -> 自己已发出的 command[k]
k >= t      -> 候选 a，表示从当前步起未来持续发送 a 的候选计划
```

在同一个当前观测上，按照上述作用命令与固定名义动力学依次推进。历史段使用实际存储的已发出命令，不能用上一步命令填满，也不能从仿真器实际执行历史复制。当前候选只在选中之后加入真实发送历史；虚拟未来不能污染真实历史。`immediate` 组每个预测步都直接作用 `a`，保持原执行假设。

两组都保留原常值候选的命令努力成本和与上一发送命令的变化成本；不把真实已执行命令替换进努力成本形成另一个未声明改动。所有候选的历史前缀相同，但其预测状态仍须进行可行性检查。即使未来命令尚未生效，历史命令也可能导致预测越界。

实际仿真器仍采用前一批的永久历史索引抽象：`command[t - d_true(t)]`，负索引为零。延迟突增会回读和重复执行旧命令。该定义不代表物理通信队列；本批不同时改造执行模型。突变不清空历史，不构造新零队列，不给控制器发“延迟已变为 30”的通知。

每个方法在发出命令后、读取下一状态前保存因果单步预测。历史组使用其 `d_declared` 对本步作用命令的推断，立即执行组使用本步新命令。周期外力不进入预测，继续保留原扰动失配。另为所有方法保存“名义模型把新命令立即执行”的公共残差，便于分清反馈模型变化与实际控制变化；公共残差仅离线计量，不参与本批动作选择。

无候选可行时使用既有零命令回退，只对本稳定受支撑试验模型解释；它不能撤回已经发送的历史命令，也不代表一般机器人的安全恢复动作。独立状态检查决定早停，不等待门控或补充反馈。

另记录使用仿真器实际历史作用命令、固定名义动力学计算的单步残差，用于离线区分命令时序失配与动力学失配。它只在 transition 完成后计算，属于特权诊断，不能参与控制器预测或动作选择。每步三次诊断单步预测（方法因果预测、公共立即执行预测、作用命令标签预测）分别与候选搜索计账。

## 5. 预先指定的机制诊断

`d_declared = 30, H = 20` 时，本步候选在所有预测状态中均未生效。49 个候选的状态误差与预测可行性完全一致，选择只受命令努力和变化项影响。零初始命令下可能持续选择零。这一组必须保留为**时域不足诊断**，不能用它单独否定历史预测。日志应记录候选能够影响的预测 transition 数 `max(H - d_declared, 0)`：本组为 0，H50 对应为 20。

`d_declared = 0` 时，history 与 immediate 的数学定义一致；同一时域必须产生一致的命令、预测、轨迹和退出。延迟 0→30 突变及增益下降场景的声明延迟也是 0，两种模型在同一时域依然应保持一致；不得把 hidden true delay 或 gain 偷送给 history 组来制造适应收益。

延迟 15→30 场景的 history 组在突变前使用正确初始延迟，突变后继续固定使用 15。结果须分别报告突变前预测改善和突变后的失配，不声称已经识别新的延迟。延迟突变发生时各方法状态不同，前一阶段已接近目标的组可能更容易保持稳定；整条连续轨迹的配对结果不能当作相同突变起点下的纯适应能力。

忽略周期外力、在静态目标处计算需要发送的命令：

```text
u_required = (stiffness * target + coupling * (target - reverse(target))) / gain
gain = 1     -> (0.245, -0.213)
gain = 0.25 -> (0.98, -0.852)
gain = 0.125 -> (1.96, -1.704)
```

离线按所有既有 `STAGES` 和独立硬命令限额分别计算静态目标可达性：

| 实际增益 | 所需命令 | 第 0 档 `(0.4, 0)` | 第 1 档 `(0.7, 0.7)` | 第 2 档 `(1, 1)` | 硬命令限额 `(1.2, 1.2)` |
|---|---|---|---|---|---|
| 1 | `(0.245, -0.213)` | 不可达：关节 1 未开放 | 可达 | 可达 | 可达 |
| 0.25 | `(0.98, -0.852)` | 不可达 | 不可达 | 可达 | 可达 |
| 0.125 | `(1.96, -1.704)` | 不可达 | 不可达 | 不可达 | 不可达 |

增益 0.25 所需命令仍位于本批最高权限内，却超过前一批中档限额，不能笼统归因于物理上无力保持目标。增益 0.125 则连独立硬命令限额都不允许静态目标，是物理控制作用不足的对照；历史预测或延长时域不能凭空增加力矩能力。固定模型失配、权限、动作离散化和物理能力限制需分别解释。

这些计算只作离线审计，由真实仿真增益得出，不能用于修改模型、控制或权限，也不能据此证明动态任务必然可达。它们只适用于无外力静态目标；周期外力、瞬态和离散常值候选会进一步影响控制。本批所有实际方法仍固定最高权限，低档可达性表只用于解释既有负结果。

## 6. 日志、指标与主要比较

保存每个运行的完整配置、初态、seed、实际步数、退出原因、源代码 commit/dirty 状态、源文件 SHA-256、Python/NumPy/系统版本与 CPU 字段。参数学习更新计数明确为零，运行前后检查动力学、声明延迟、增益、规划配置和源文件指纹。

逐步日志至少包含：

1. 0-based 命令步、已完成步、物理时间、实际场景阶段与固定前后半段索引。
2. 当前观测、产生的新命令、自己的历史长度、模型假设、固定声明延迟、时域、候选影响 transition 数、所推断的本步作用命令与因果单步预测。
3. 实际下一状态、实际历史作用命令及其源索引、真实参数、有效力矩、外力；这些仅由实验记录层保存，不能反传控制器。
4. 因果残差与公共立即执行残差、两关节目标误差、状态是否有限/安全、可行候选数、回退、当前命令违规、有效力矩超名义硬限额等字段。
5. 每步实际规划内部状态推进数、动作选择耗时；计算量与真实交互分别汇总。

归一化残差保持前一批定义：位置用 `0.35 rad`、速度用 `1.2 rad/s` 归一化后计算四维 RMSE。它是观测残差，不是校准的不确定性界。两关节目标 RMSE 使用 rad。整体、前 225 步、后 225 步与实际 pre/post-change 阶段分别计量，早停未执行部分记缺失并报告样本数。

主要比较是同一场景、同一种子、相同时域的 `history` 对 `immediate`，同时查看残差、完整预算率、状态退出、全目标误差、有效控制作用和计算量；再比较各执行假设的 H20 对 H50。PD 始终是固定全权限参照。不得将更低残差、无退出或零命令独立当作任务成功；3 个种子仅用于机制开发，不作普适优势的统计主张。

无训练原型范围、已知初始延迟的额外先验、动态变化未识别、H50 计算成本、稳定支撑条件和所有不利结果必须出现在结果说明中。

## 7. 测试与验收

正式矩阵前运行相关测试并检查变更。测试至少覆盖：

1. 零延迟逐候选预测、动作与原规划器兼容；同一时域 `history/immediate` 零延迟闭环一致。
2. 延迟负索引为零、历史边界与历史最后一项、首个候选生效 transition，无 off-by-one；未来常值候选不写入真实历史。
3. 用手工推进检验非零历史、固定延迟与多步预测；更改未来候选不影响延迟前缀。
4. H≤delay 时状态与可行性对候选相同；H>delay 时候选在恰当 transition 开始影响状态。
5. 延迟突变保留命令与状态历史、控制器声明值不更新；不同 hidden plant 参数在相同当前观测及自有历史下不改变控制器输出。
6. 缺失历史、非法延迟、非有限输入、形状错误被明确拒绝，不能静默读未来或用仿真器字段补全。
7. 历史导致的全部候选不可行回退；独立状态早停优先、预算与内部计算计数准确；不丢弃早停轨迹。
8. 固定参数及来源指纹一致；归档 JSON 无 NaN，压缩 CSV 行数等于实际执行步数，源快照和清单可核验。

测试后冻结并提交实现，在干净的已提交代码上运行一次正式矩阵。归档至少包含协议、逐运行报告、逐步轨迹、源文件快照、校验清单与结果解释；不能根据看到的结果调整候选、时域、声明延迟、扰动或挑选种子。验收是时序、信息边界和证据可审查，方法有利与否都如实交付。

下一阶段的延迟估计或增益在线辨识属于参数学习，必须等用户明确要求开展学习实验后再启用。本批只建立固定模型对执行历史的处理、预测时域不足和未知变化的可复核证据。
