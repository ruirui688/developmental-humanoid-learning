# 发育式机器人学习：项目推进路线

> 更新日期：2026-10-10
>
> 状态：下一阶段研究设计；已完成的二维、PBHC/G1 工程与地面发育记录单独保留，不代表新在线学习候选已验证。
>
> 本轮目标澄清：少量真实交互、在线身体认知、能力门控与技能积累；减少对海量仿真 PPO 和预训练任务策略的依赖。

当前资源与执行范围：仅使用 CPU，用户要求当前阶段不训练。[固定模型的无训练机制验证](CPU_VALIDATION.md)已完成；以下在线辨识和模型更新仍是后续任务，不因推进路线存在就自动启动。仓库已接入 PBHC + Isaac Gym G1，已有 GPU 工程审计与地面发育开发记录来自另一台机器，本轮未复现。当前优先复用和阅读这些接口、配置与冻结日志，不重做已有资产和映射；Isaac Lab 仅为未来可选迁移后端。

后续 [无训练压力矩阵](CPU_FAILURE_RESULTS.md)已完成 144 次运行：发现延迟下的位置退出，并发现持续表现失败退级变体损害增益下降后的跟踪表现。该变体仅保留为对照；先区分模型失配、动作滞后与执行器能力不足，再考虑权限撤回、控制补偿或后续学习。

## 1. 我们要解决什么问题

长期目标是让没有预训练站立或行走策略的机器人，在独立安全系统保护下，通过真实交互认识身体、形成协调能力，并逐步获得运动技能。

用户已明确这一原初目标同样适用于二维火柴人。主轨应验证小孩式的感觉运动探索与技能形成，不预先提供特定步态教师或已会走的策略。旧 DHP-PPO 的教师与参考轨迹相关环境属于含任务先验的历史对照。当前无训练工作先审计和准备独立纯发育变体：初始化、观测、奖励与物理推进均须检查，仅关闭教师不构成纯发育实验。具体依据见 [火柴人机制对比](STICKMAN_CPU_COMPARISON.md)。

这一准备现在落实为独立 [CPU 地面身体探索物理底座](GROUND_BODY_PHYSICS.md)：MuJoCo CPU、自由基座和 8 个力矩关节、四种躺姿、物理接触、原生观测与特权日志隔离。当前只做固定随机/零力矩采集与物理验收，不训练身体模型，也不把被动运动计为技能获得。

近期先回答一个范围可控的问题：

> 在受支撑的局部姿态和重心控制任务中，自监督身体建模、局部预测控制与能力门控，能否比固定控制或直接 PPO 用更少交互获得稳定能力，并在动力学变化后更快适应？

PPO 作为学习方法的对照；优先验证的候选是“在线系统辨识／自监督身体模型 + 局部预测控制 + 能力门控”。它是否优于强化学习尚待实验，不能预设结论。

“减少强化学习依赖”具体指减少以任务奖励反复训练策略的需求。算法仍需要控制目标、预测误差、约束和动作选择规则。“直接在真实环境学习”允许经过仿真测试的程序与安全控制，但需要明确初始模型和已有任务能力。

不承诺半小时学会走路、不把任意未知环境作为首个任务，也不以消除所有先验为目标。先验的种类、来源和作用必须可审计。

## 2. 从生物发育提取什么

这里使用功能层面的工程假设，不把类比当作已证明的生物机制，也不声称 G1 会产生肌肉生长。

| 生物启发 | 工程对应 | 要检验的结果 |
|---|---|---|
| 活动影响身体与控制能力的发展 | 根据已有身体能力逐步调整控制权限 | 减少高风险探索，避免长期停留在简单阶段 |
| 运动与感觉共同形成身体认知 | 用动作与原生传感历史学习预测模型 | 提高闭环控制和变化后的适应能力 |
| 局部协调减小控制难度 | 平滑动作、低维协同或局部反馈 | 相同交互预算下更快建立有效控制 |
| 能力积累支持新技能 | 复用身体模型、反馈参数和局部技能 | 新任务收益超过从头学习且不遗忘旧能力 |
| 先天结构与后天校准共同作用 | 明确初始结构，测量在线校准贡献 | 区分初始能力与交互带来的改善 |

机器人的电机额定能力不会因练习增长。扩大动作／力矩权限只表示在固定硬件安全上限内，更充分地使用已有能力；增益、支撑与权限的变化会改变系统动力学，身体模型必须感知这些条件。

## 4. 先验和预算如何分类

每个实验先填“初始拥有的能力”，再讨论学习效率。

| 类别 | 例子 | 记录要求 |
|---|---|---|
| 公共身体与安全信息 | 机器人资产、关节限位、传感器标定、底层伺服 | 所有组共享，记录版本、参数与差异 |
| 通用算法结构 | 预测模型形式、平滑性、结构化探索、优化器 | 披露结构、超参数、开发集调参预算 |
| 任务相关控制先验 | 已调好的站立反馈、解析步态、技能基元 | 明示其初始任务成功率和使用组别 |
| 外部数据／教师 | 动作轨迹、预训练策略、接触教师标签 | 披露许可、数据量、教师调用和预训练成本 |
| 在线经验 | 校准、探索、控制、恢复和学习用评估 | 全部计入交互账本，不能隐藏失败或热启动 |

安全控制若会主动完成平衡或恢复，应同时被记录为控制先验。安全约束的存在可以共享，但不能把其任务能力算成新方法学习所得。

纯发育轨无预训练任务策略；人体／教师先验轨另行报告。仿真接触标签可以监督估计器，但在线控制器只能读取部署时实际可用信号。

预算至少分开记录：物理／仿真控制步、动作尝试、探索时间、校准时间、适应时间、失败、复位、支撑量、外部样本、教师调用、离线更新、在线计算、墙钟时间、CPU／GPU 时间和能耗。学习预算与评估预算分开且全部报告；评估反馈进入更新时归入学习预算。纯计算时预测的候选轨迹不算物理交互，但须记录计算成本；规划器查询真实仿真器则单列模拟查询预算。

## 5. 最小算法架构

```text
关节／IMU／力矩估计／控制指令历史
                  ↓
状态估计 + 局部身体预测模型 + 模型不确定性
                  ↓
当前技能目标 + 小范围候选动作／局部预测控制
                  ↓
能力门控：关节、幅度、速度、探索、支撑条件
                  ↓
独立安全控制器 → 底层伺服 → 身体
                  ↑                 │
                  └──反馈与数据记录─┘
```

初版只做局部预测，先使用可解释的局部线性／残差模型、经典系统辨识与小范围候选动作；神经网络的必要性与收益另行验证，不默认更复杂模型更好。接触先固定，再研究切换；准确动力学只能作为明确标注的诊断上界，不能偷偷提供给主比较方法。

- **冷启动**：模型未知时只能使用预定的低风险、小幅动作和受保护姿态；预测不可信时暂停学习控制，进入已验证的安全状态或人工复位。若根本没有安全动作集合，记录阻塞，不能靠未知模型证明首批动作安全。
- **身体模型**：预测状态增量或局部响应，输入包含动作历史、支撑条件、动作权限和增益；在终止／接触模式切换处保留真实转移，避免把 reset 后状态当作身体响应。
- **不确定性**：用留出轨迹误差、残差或模型间分歧估计可信范围，检验预测区间覆盖率／校准情况；这些估计不能当作形式化安全保证。候选动作超出已验证区域时缩小幅度，不能因预测均值正常就扩大权限。
- **控制延迟**：记录指令、采样与实际响应的时间戳，辨识执行器滞后，统一控制频率；模型使用历史动作而不是假定指令立即生效。
- **在线更新**：先在副本中更新，通过短窗口验证后切换；保留最近可用模型与回滚路径。优化超时、数据异常或验证失败时使用安全回退。
- **探索选择**：仅在安全动作集合中比较随机、平滑与信息导向探索。探索目标不能鼓励不可控接触或追求大预测误差。
- **技能积累**：起步只保存“局部姿态保持／小重心转移”的目标、适用状态和模型，不建立大而空的全身技能库。

能力门控使用预先冻结的预测误差、校准后的不确定性、任务成功、风险和实际闭环恢复标准；要求连续窗口通过，并有晋级／退级滞回和最短停留时间。记录权限与支撑轨迹、停滞原因，不能仅因训练误差降低就晋级，也不能通过永远停留在小动作来换取低失败率。承重任务的力矩下限必须满足可行性，低力矩本身不等于安全。

## 6. 分阶段推进与验收

阶段 0–2 先在 CPU 上验证机制，当前只执行其中无训练的部分。阶段 3 复用既有 PBHC/G1 基础设施，静态接口、配置与日志接管可以并行且无需 GPU；恢复动态验证需要兼容 GPU 和用户允许的执行范围。所有 G1 控制使用同一 canonical 映射；新后端或变更资产须重做对应审计，不把历史 smoke 视为新配置的验收。

### 阶段 0：冻结研究协议，确认代码可信度

**成果**：实验协议、初始先验清单、交互账本设计、基线配置与修正后的代码检查记录。

**工作**：核查 PPO 动作概率与边界、终止和时间截断、Body Schema 的真实转移目标、随机种子和实验元数据。静态怀疑需用可复现案例确认后修正，不直接把疑点当成结论。

**验收**：相关测试与 `git diff --check` 通过；新实验能恢复完整配置、源代码 commit／dirty 状态与逐种子指标；任务、成功标准、预算和模型选择规则在正式测试前冻结。

**失败处理**：先修代码或日志，保留旧结果并标记版本；不通过追加训练掩盖实现问题。

### 阶段 1：低风险局部身体模型 CPU 原型

**成果**：独立、有明确物理响应的低维关节／受支撑平衡任务，可先用 CPU 解析动力学；配套安全探索器、在线辨识器与误差／不确定性报告。

**工作**：从少量关节或低阶关节—躯干系统开始，先固定接触模式；惯量、阻尼、增益、执行器延迟对学习器未知。现有 `IdealStickmanEnv` 只能辅助接口调试，其速度代理不能提供新方法的物理收益证据。

**验收**：未见连续轨迹上的单步／短期预测优于冻结模型或简单持久性预测；多个预定 seed 无非法动作和 NaN；已知注入的延迟／参数变化能反映在模型误差或可信度中。冷启动校准与已有模型对未知载荷／增益／延迟的适应分别评估。

**失败处理**：检查激励不足、时间同步、观测不可辨识和模型形式；缩小状态／动作范围。模型误差尚未解决时不增加全身自由度。

### 阶段 2：闭环控制与能力门控对比

**成果**：局部预测控制、姿态保持／小重心转移任务、固定与能力门控对照，以及变化后的适应曲线。

**工作**：共享模型和探索基础，对比持续更新与冻结；再比较固定进度和实测能力晋级。先测控制收益，再增加模块。

**验收**：在冻结预算和测试条件下，报告学习前控制水平、在线更新净收益、达到成功阈值的交互、风险、计算延迟及完整失败 seed；证明预测改善是否转化为控制改善；门控日志能说明每次晋级／退级原因。若收益只发生于变化后，只声称适应提升。

**失败处理**：控制失稳时先检查模型误差、规划时域和延迟；门控长期不晋级时区分任务不可达与标准不合适。任何标准修改只能在开发集完成，重新冻结后再正式评估。

### 阶段 3：复用 PBHC/G1 接入，按需迁移仿真后端

**已有成果**：PBHC + Isaac Gym 接入、来源与资产校验、canonical joint／body／action 静态检查、执行器和接触审计、GPU smoke 与 evaluation-only 工具；见 [PBHC 接入记录](PBHC_INTEGRATION.md)。这些是历史主机上的证据，本轮 CPU 未重新运行 GPU 链路。

**工作**：先在 CPU 阅读上游来源清单、验证脚本、现有映射与部署观测接口，检查新控制模块的状态/动作定义。兼容主机可用且执行范围允许后，复核加载、限位、逐关节方向、增益、接触分组和 reset。只有明确需要 Isaac Lab 或其他后端时才建立隔离适配包，保留同一资产身份和映射，并单独记录转换、接触语义及控制差异。

**验收**：静态检查与既有 canonical 映射一致，新模块不得复制一份漂移的关节表。恢复动态运行或变更后端后，接触标签、控制响应与 reset 在对应场景通过检查；参与大规模比较的每种方法须通过自己的短运行和日志检查。历史近站立 checkpoint 仅用于工程审计，不作为地面冷启动学习的初始策略。

**失败处理**：先修模型、配置或依赖；缺兼容 GPU 就记录资源阻塞，继续 CPU 原型。不得为绕过阻塞静默重装系统、驱动或破坏二维环境。

### 阶段 4：G1 受支撑站立与小重心转移

**成果**：同一任务中的经典控制、Direct PPO、在线模型控制和门控对照；原生观测输入与接触教师标签的隔离验证。

**工作**：先测经典控制与底层控制的初始表现，再验证在线模型控制，并建立可复现的 Direct PPO 对照；PPO 训练不是新路线原型的前置条件。先固定接触与强支撑，逐步减少辅助，最后检验小扰动、载荷、摩擦和延迟变化。原生信号不足时再加入接触估计，并单独消融。

**验收**：统一无额外支撑或指定支撑条件评估；报告达到相同成功标准的交互、支撑暴露量、严重失稳、冲击、饱和、人工／模拟复位及墙钟成本；接触估计效果与控制收益分开报告。

**失败处理**：退回较强支撑或较小任务；原生信号可能无法唯一辨识摩擦和接触位置，此时明确限制或评估必要信号，不能将仿真真值暗中输入部署控制器。若新方法未胜过经典控制，报告负结果并检查任务是否需要在线学习。

### 阶段 5：受保护真机中的局部在线学习

**成果**：经授权的低风险采集与闭环试验报告，展示在线身体校准／变化适应，而不是直接宣称自主行走。

**前提**：用户明确授权、现场人工监护、独立急停、关节／电流／力矩／速度／温度限制、软垫或吊架、低风险初始姿态全部具备；仿真及离线验证通过。安全控制不受学习模块覆盖。

**验收**：先验证只读采集和时序，再执行单关节小幅探索，最后进入局部闭环；预算、停止条件与人工干预规则预先冻结。报告初始能力、每次更新、真实动作次数与全部异常。

**失败处理**：失稳趋势、异常电流／温度、通信延迟、传感故障或独立安全干预触发立即停止或安全回退；线下分析后再决定下一次试验。未经授权或安全条件不足，停留在仿真和离线阶段。

本路线的 CPU 在线模型候选，先在局部任务验证后再扩展到翻身、起身和行走。已有 G1 地面轨的翻身/支撑进展继续保留；它尚未证明该候选路线，也不要求首篇实验完成完整技能链条。

## 7. 公平实验怎么设计

实验按研究问题逐步增加，不同时堆叠全部模块。正式测试使用未参与调参的 seed，匹配任务、初始状态、动作定义、控制频率、安全边界、支撑条件分布、终止与评估规则。

| 对照 | 要隔离的问题 |
|---|---|
| 经典反馈／名义模型控制 | 任务是否无需学习即可完成；已有控制知识价值多少 |
| 相同模型与控制器，在线更新关闭 | 改善是否来自持续学习，而非初始模型／控制器 |
| 固定成熟 vs 能力门控 | 根据能力晋级是否优于预定进度 |
| 安全探索开启 vs 关闭 | 额外探索的数据与代价是否值得 |
| 随机／平滑探索 vs 信息导向探索 | 探索结构是否提高辨识与控制效率 |
| Direct PPO 与必要的强基线 | 新路线与奖励驱动策略学习的实际差异 |
| 必要组件移除 | 身体模型、接触估计和技能复用各自是否贡献收益 |

经典控制器使用的解析模型、人工调参和任务知识也须披露；冻结模型对照与更新组拥有相同初始模型。探索关闭组按同一总物理预算执行任务，不能只让开启组获得额外交互。

固定与门控组可以产生不同支撑历程，这是机制的结果；比较总风险时同时报告各权限／支撑阶段的暴露时间，在统一评估条件下测最终能力。少开放动作或支撑更多导致少失败，不足以证明能力提高。CPU 原型与 G1 的结果分别陈述。

若冻结控制已解决任务，缩小“在线学习必要性”的贡献；若简单辨识同样有效，不声称复杂身体模型的优势；若门控收益仅来自支撑更多，缩小或否定能力门控提升技能的解释。失败结果应决定研究问题的调整。

正式报告不只给终点成功率，还应包括成功率—交互曲线、达到阈值所需预算、峰值风险、复位与计算成本。未达阈值者记为预算内未达，不能删去或假定其已成功。

## 8. 数据切分与两类学习成本

- **开发集**：选择模型形式、增益、门控阈值、规划时域与超参数；记录调参规模。
- **验证集**：选择检查点／配置，确定停止规则；不与正式测试轨迹混用。
- **正式测试集**：冻结配置后测试未见 seed、完整轨迹和参数组合；按 episode／轨迹切分，避免相邻窗口跨集合。
- **在线评估**：主结果在指定检查点冻结模型评估；持续更新的部署评估另报，允许更新时必须计入其交互并说明反馈来源。

**冷启动实验**：从相同初始知识开始，计入第一次校准、探索、恢复和达到能力阈值的全部交互，不使用先前任务数据热启动。

**适应实验**：从指定的已具备能力的状态出发，在未见载荷、阻尼、摩擦或延迟变化后计量恢复交互。更新组和冻结组共享变化前状态；模型集成等额外计算单列报告。

两类成本分别展示；“变化后快速恢复”不能被称为“从零快速学会”。跨技能复用还要计入此前技能成本，并验证旧技能是否遗忘。

## 9. 现在即可执行的待办

当前先遵守 CPU 无训练范围：运行固定模型验证与异常测试，整理模型失配下的结果。下列参数学习任务暂不执行，直到用户另行要求进入学习实验。

1. 归档 CPU 固定模型验证的源码、逐 seed 指标和证据边界，补足历史与新增实验的溯源；可验证进度按用户授权提交并推送。
2. 复用 `src/developmental_control/`，继续无训练的固定模型、权限、门控与失效检查，冻结后续局部任务协议。
3. 在 CPU 上接管 PBHC/G1 的来源、静态映射、观测/动作接口与冻结开发数据，明确历史近站立工程轨和地面学习轨的区别；不运行其训练入口。
4. 后续用户明确要求学习实验后，加入相同初始化的冻结／在线辨识对照，再评价闭环控制与门控收益。恢复 G1 GPU 运行或迁移 Isaac Lab 另需确认实际资源与相应验收。

上述按验收推进，不预设必胜结果和日历工期。每个阶段交付配置、原始逐种子指标、源代码版本与失败诊断，阶段验收后才扩大规模。

现有 CPU 代码位于独立 `src/developmental_control/`，现有 G1 扩展位于 `src/developmental_g1/`，上游配置与脚本分别保存在 `configs/pbhc/` 和 `scripts/`。按需新增后端适配层，仿真器依赖不能进入轻量 CPU 原型的导入路径；不为切换路线重建上游机器人资产。

### 第一个实验 E1：身体辨识是否改善局部控制

| 协议项 | 第一版建议 |
|---|---|
| 对象 | 单关节或两关节的 CPU 动力学任务，含惯量、阻尼、伺服响应和可配置延迟；先固定接触，不使用步态速度代理 |
| 控制目标 | 在规定动作范围内跟踪小幅目标轨迹，测量误差与越界；通过后再扩展到受支撑平衡 |
| 已知信息 | 关节定义、标称参数、安全范围与目标；学习器不能读取任务真实参数，初始信息各组共享 |
| 第一对照 | 相同初始模型和控制器的冻结组／在线更新组；加入简单递推辨识，复杂神经模型后置 |
| 数据 | 先用同一低风险校准前缀初始化，随后各组按相同总交互上限控制；初始校准费用计入每组预算 |
| 两类问题 | 从初始知识出发的校准与控制获得；从已校准系统出发的未知载荷、增益或延迟适应，分别报告 |
| 主指标 | 同一检查点冻结模型后的闭环误差、达到预定控制标准的总交互、越界/干预和计算延迟 |
| 辅助指标 | 留出连续轨迹的预测误差、区间覆盖率、模型参数/残差变化；预测改善不能替代主指标 |
| 成功与停止 | 在开发集制定轨迹、误差、持续时间、风险和预算阈值，写入配置后冻结；到上限仍失败的 seed 保留 |
| 失败解释 | 更新无闭环收益则不扩大任务；若简单辨识同样有效，采用简单方法；若仅适应有效，只报告适应贡献 |

E1 只验证身体建模与控制的因果联系，不证明 G1 站立或技能累积。模型与控制收益成立后，E2 加入固定／能力门控；E3 再比较局部技能复用与从头学习，并把此前技能获取成本计入总预算。

## 10. 当前不要做什么

- 不先跑大规模 PPO，再事后寻找生物解释；不在映射和 smoke 通过前开始 G1 长训。
- 不直接用现有二维步态成绩证明身体模型、能力门控或真机学习有效。
- 不把硬件权限解锁称为真实肌肉生长，不把仿真特权状态当作部署原生观测。
- 不同时开发全身触觉、全套技能库和翻身到行走全部任务。
- 不用已会站立／行走的策略初始化后仍称无预训练任务策略；不隐藏人工控制与支撑提供的能力。
- 不运行未经授权的真机动作，不绕过独立安全限制，不为进度静默安装驱动或重装系统。
- 不下载未决定使用的数据或未知 fork，不把原始数据、外部源码或大型权重直接提交本仓库。
- 不覆盖历史验证结果，不省略失败 seed；按用户明确授权持续提交并推送通过检查的中间进度，保留远端已有工作。
