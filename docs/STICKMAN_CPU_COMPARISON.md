# 火柴人为何能走：与 CPU 固定模型原型的机制对比

本次只读分析以源码提交 `2d032f0` 为检查基点，结合已有二维验证数据；没有运行训练、参数拟合或新增控制矩阵。历史二维元数据没有精确源码提交字段，因此下面的代码解释基于当前仓库实现，不替代历史源码逐字节溯源。

**用户澄清后的定位：火柴人也应模拟小孩通过探索和反馈学习运动，这是项目的原初目标。** 下文的教师、预训练与代理环境是在解释旧实现实际为何成功，不是在认定它们符合该目标。将既有任务教师当作小孩发育的合理起点，会混淆先天结构和提前提供动作答案。旧结果保留为含任务先验的对照；纯发育主轨需要补齐。

主轨可保留身体结构、感官、底层伺服和安全边界，通用探索/协调结构也应披露并测量初始能力。特定左右交替步态、屈膝轨迹、为保持站立专门调好的反馈和预训练任务策略属于任务先验，不能隐含提供给主轨。模仿小孩强调“低风险动作探索 → 感知后果 → 身体认识 → 协调和支撑 → 逐步获得技能”，不要求把所有人类生物机制逐字复制。

已有火柴人成功必须保留：五个种子 10–14 的完整 DHP-PPO 方案在规定无支撑评估中成功率均为 1，Direct PPO 均为 0；同为 76,800 次环境交互/方法/种子时，训练严重跌倒减少 95.51%。DHP 另使用 8,192 个合成先验样本和 120 次先验监督更新，训练过程中仍有先验损失。关节跟踪 RMSE 为 DHP 约 0.316、Direct 约 0.273，组合收益不能只用有利指标解释。数据见 [逐种子指标](../results/validation/metrics_by_seed.csv)和 [运行元数据](../results/validation/run_metadata.json)。

## 1. 两套实现回答不同的问题

| 对比项 | 二维火柴人 DHP-PPO | 当前 CPU 原型 |
|---|---|---|
| 要完成的任务 | 在理想二维规则中保持躯干稳定并表现周期步态和前进 | 受支撑两关节跟踪固定目标，诊断延迟、增益等失配 |
| 初始知识 | 解析步态教师、步态时钟、平衡反馈、任务条件 | 标称物理模型、固定目标、成本权重；历史组额外有声明初始延迟 |
| 参数学习 | 先验监督初始化，再执行 PPO、先验损失和身体预测辅助损失 | 模型、策略、增益、声明延迟更新为 0 |
| 动作空间 | 四关节连续位置目标，由固定伺服执行 | 两关节每关节 7 个力矩候选，未来计划假设保持常值 |
| 发展机制 | 固定更新次数的五阶段课程，逐步撤掉外部支撑 | 显式权限状态机，或固定共同最高权限 |
| 身体模型用途 | 共享编码器的辅助训练目标，未用于动作预测搜索 | 直接预测候选的后果，再按成本选择动作 |
| 时间与知识积累 | 同一策略跨阶段保留参数，环境状态在换阶段时重置 | 每步重新规划，但固定参数不从反馈积累新知识 |
| 物理范围 | 关节伺服、单轴躯干倾角及前向速度代理 | 受支撑弹簧阻尼关节的明确状态推进，尚无双足平衡或接触切换 |

火柴人实现本身指定 CPU。它能成功不能证明需要 GPU，也不能用本轮“暂不训练”的零更新实验与已完成训练的策略直接比较成功率。完整学习路线和阶段约束见 [推进路线](DEVELOPMENT_ROADMAP.md)。

## 2. 火柴人成功的可解释机制

**先验已经提供了可用的协调方向。** [human_prior_action 与预训练](../src/robot_rl/ppo.py)给出左右髋反相的正弦步态、摆腿屈膝以及 `0.70 × tilt + 0.12 × tilt_rate` 髋部平衡修正。在 PPO 前用合成样本拟合策略，之后继续以先验损失约束策略。先验与 [环境参考轨迹和解析专家](../src/robot_rl/env.py)的构造高度一致，减少了需要探索的动作范围。[现有专家单元测试](../tests/test_env.py)证明解析专家不需要参数学习，也能在该环境中运行 250 步不跌倒、末段平均速度超过 0.75；这不是对先验拟合网络的完整成功率评估，但说明教师已经包含本任务可用的控制能力。

**训练从有支撑到无支撑逐步变难。** 外部支撑按 `1.0 → 0.55 → 0.35 → 0.18 → 0` 变化；它直接改变躯干的有效刚度和阻尼。全支撑阶段躯干倾角有恢复作用，无支撑时需要主动反馈。这提供较低风险的训练条件。同一策略跨阶段保留参数。旧二维课程将 40 次 PPO 更新固定均分到五阶段，每阶段 8 次；它不是当前 CPU 或 G1 的能力门控，不能混称为由能力证据决定晋级。

**策略持续更新，并可输出随相位变化的动作。** PPO、先验损失与身体预测辅助损失共同训练小网络；策略能够随当前倾角、速度、相位和任务条件连续改变四关节位置目标。身体预测头通过共享编码器辅助学习表征，在 `act()` 中没有被调用来执行 MPC。原方法的“Body Schema”与新原型的固定动力学规划并不是同一种控制路径。

这些机制能解释完整方案为何容易在本环境中取得成功，但现有组合对照尚不能分别归因于先验、课程或身体预测头。训练流程明确存在 PPO 更新，也没有记录先验拟合后的学习前成绩，所以不能量化 PPO 新增加了多少能力。

## 3. 环境如何定义“前进”

[火柴人环境](../src/robot_rl/env.py)采用以下前向速度代理：

```text
gait_quality = exp(-2 × joint_tracking_MSE)
upright_quality = exp(-5 × tilt²)
desired_v = target_speed × gait_quality × upright_quality
vx += dt × 3.2 × (desired_v - vx)
x += dt × vx
```

因此，较好的参考轨迹匹配和躯干稳定会直接产生前进速度。代码没有通过足底摩擦、地面反作用力或刚体冲量求出前进；足是否真正承重、推地或滑动不参与该速度计算。步态相位固定以 1.15 Hz 推进；“脚接触”标志由相位正负生成，不能当作碰撞传感。起点接近直立，没有地面翻身或起身过程。

[录像骨架](../src/robot_rl/evaluate.py)按关节与躯干状态绘制，髋部高度固定为 1.05 m；它是代理状态的可视化。已有验收仍具有明确意义：在这个理想任务中，策略无支撑运行 12 s，不跌倒、平均速度不低于 0.70、关节 RMSE 不高于 0.38。它支持周期协调和简化平衡任务的概念验证，尚不能证明足地接触下的真实双足行走。

## 4. 当前原型为何仍会遇到零命令和退化

[固定候选规划](../src/developmental_control/planning.py)与 [历史规划](../src/developmental_control/history_planning.py)每步从有限力矩候选中选择一个，虚拟未来假设同一命令持续发送。它没有旧策略已学得的相位动作模式，也不从执行反馈更新模型。

在声明延迟 30 步、时域 20 步时，新命令在预测结束前尚未生效，状态成本无法区分候选；零初始命令下努力与变化成本使规划持续选择零。在声明延迟 15 步的 H20 中尚有 5 步候选作用，却也全程零命令，说明不能只怪候选完全不可见，成本、候选分辨率和常值计划假设需进一步拆开。H50 在名义和弱增益场景又更差。原始结论见 [历史/时域结果](CPU_HISTORY_RESULTS.md)。

门控也不同：撤回动作权限不能修正错误身体模型；弱增益下撤回权限还可能使静态目标不可达。前批更多退级造成 24.86% 跟踪恶化，见 [失效结果](CPU_FAILURE_RESULTS.md)。新原型的问题不表示旧火柴人成果失效，它暴露的是另一套动作选择与固定知识假设的限制。

## 5. 如何把已有成果连接到下一步

1. **先恢复纯发育主轨的设计边界。** 审计策略初始化、观测、奖励和动力学是否提前包含步态答案。旧 `body_babbling` 已使用步态幅度 0.35 和跟踪权重 2.5，起点仍接近直立；仅有发育阶段名称不足以实现小孩式身体探索。只关闭先验预训练或 prior loss 也不够，参考步态跟踪、速度代理和相位接触仍需独立处理。先准备独立变体与无训练验收，不覆盖旧环境、检查点和原始结果。
2. **保存含任务先验的二维基线，并拆分能力来源。** 后续对照包括解析教师、先验拟合后 0 PPO、相同先验的 Direct PPO、课程与身体预测头消融。它们作为对照帮助定位能力来源，不替代纯发育主轨。额外先验预算单列；当前不启动新的拟合或 PPO。
3. **修正无训练动作选择问题，服务于探索与反馈控制。** 在相同时域、权限与观测下分别诊断成本和候选分辨率，保留所有退化；不把固定双关节目标跟踪当作已经形成发育式技能，也不默认给主轨添加已会走的动作生成器。
4. **之后单独检验在线身体更新。** 固定与更新模型共享初始化和交互预算，控制器只读取自身动作与可用反馈；更新必须带来闭环收益，不能只降低预测残差。在线辨识属于学习阶段，保持待启动。
5. **增加承重和接触真实性。** 在有真实重力与接触的局部任务中，让动作后果由物理推进产生，再扩展自主形成的协调与技能。已有 G1 工程与地面发育证据可复用，但不代表新在线路线已成功。

生物启发中可以借鉴“初始结构 + 感觉运动探索 + 反馈学习 + 渐进发展”。基因、身体和神经结构可能提供运动倾向；算法中采用相应结构须明确其内容和学习前能力。火柴人的解析教师属于已知工程任务先验，不能直接等同于基因，也不能把其设计和预训练成本从账目中删除。本次仅纠正目标与证据表述，没有实现或训练新的纯发育行走策略。
