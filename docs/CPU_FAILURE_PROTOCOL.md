# CPU 无训练失效边界与门控响应协议

本协议在本批压力实验结果产生前确定，属于仓库内的实验设计记录。它不包含结果，也不是对外部注册平台的预注册。实验只运行固定模型闭环仿真与门控状态变化，不运行 PPO、监督拟合、RLS/ARX 或其他参数学习。既有 45 组低强度机制验证见 [CPU 无训练验证](CPU_VALIDATION.md)，总体阶段顺序见 [项目推进路线](DEVELOPMENT_ROADMAP.md)。

## 1. 本轮问题与判定边界

本轮回答两个问题：

1. 固定、立即执行的名义身体模型，在延迟、执行器增益与惯量变化下，在哪里出现跟踪退化、预测失配或状态限位退出？
2. 原能力门控和预先定义的“持续表现失败退级”变体，能否根据真实闭环观测识别失效并撤回权限？

当前系统是两个受支撑、局部稳定的弹簧阻尼关节，不包含人形重力平衡、碰撞或接触切换。名义物理模型、目标、固定控制器和外部支撑均属于公开的初始先验。此实验不检验身体模型学习、冷启动技能获得、算法样本效率、G1 或真机安全。

静态代码审计已显示：原门控中，持续跟踪不佳或未恢复会阻止晋级，但单凭这些条件不会撤回已开放权限。因此在看本批结果之前定义一个对照变体；保留原门控，不根据本批结果修改原阈值、增加档位或选择有利种子。

## 2. 固定配置

| 配置项 | 固定值 |
|---|---|
| 种子 | `10, 11, 12`，各方法使用相同种子初态 |
| 每次运行预算 | 最多 450 次真实仿真推进，`dt = 0.02 s`，最长 9 s |
| 初态 | 两关节位置分别由 `uniform(-0.005, 0.005)` 产生，速度由 `uniform(-0.003, 0.003)` 产生；每次运行重新使用对应种子 |
| 固定目标 | `(0.08, -0.06) rad` |
| 状态退出界限 | 任一关节 `abs(q) > 0.35 rad` 或 `abs(v) > 1.2 rad/s`；非有限状态也退出 |
| 硬命令限额 | 每关节 `1.2`；当前档位权限另行约束命令 |
| 门控窗口 | 每 25 步一个非重叠窗口，0.5 s；最后不足窗口仍保留计量 |
| 固定成熟 | 每 75 步切换至下一档，达到最高档后保持 |
| 周期扰动 | 每 25 步的前 2 步施加外部力矩 `(0.12, -0.10)`，其余步为零 |
| 参数突变 | 0-based `step = 225` 的动作开始使用突变参数，即第 226 次 transition、`t = 4.5 s`；此前为基准参数 |
| 评估结构 | 单条连续闭环轨迹，不追加一次重置后的共同权限评估 |
| 参数更新 | 身体模型、控制增益、规划规则、门控阈值更新均为 0 |

目标、传感器、初态、周期扰动和步数预算在所有方法间一致。控制器只获得当前两关节位置和速度、自己发出的命令及固定目标，不获得仿真器真实惯量、执行器增益或延迟参数。仿真参数仅用于构造场景和事后溯源。

名义参数保持既有 `JointParameters()`：惯量 `(0.8, 1.0)`、阻尼 `(1.1, 1.25)`、刚度 `(2.8, 3.2)`、执行器增益 `(1, 1)`、耦合 `0.15`、延迟 0。`FixedBodyModel` 始终采用这些参数。PD 保持已有名义前馈与 `kp = 4.0, kd = 2.0`。

`PlannerConfig()` 保持 20 步预测、每关节 7 个常值力矩候选；位置/速度/力矩/动作变化权重为 `30.0/0.2/0.025/0.04`；规划位置/速度界限为 `0.30/1.15`。这是短时域候选搜索，不是参数训练，也不保证真实失配系统保持状态安全。全候选不可行时采用原型的零命令回退，其适用范围限于本稳定、受支撑的试验系统。

档位保持既有 `STAGES`：

| 档位 | 可主动控制关节 | 每关节命令权限 |
|---|---|---|
| 0：`one_joint` | 关节 0 | `(0.4, 0.0)` |
| 1：`two_joints` | 两关节 | `(0.7, 0.7)` |
| 2：`expanded` | 两关节 | `(1.0, 1.0)` |

`GateConfig()` 保持：窗口预测残差 RMSE 上限 `0.005`、当前活动关节跟踪 RMSE 上限 `0.035 rad`、峰值速度上限 `1.0 rad/s`、窗口内最大单步归一化残差上限 `0.02`、连续通过窗口数 3、最少驻留窗口数 3。恢复条件保持窗口末 5 步的活动关节跟踪 RMSE 不超过 `0.035 rad` 且所有关节峰值速度不超过 `0.15 rad/s`。

## 3. 固定场景与方法矩阵

| 场景 | 前 225 步 | 自 step 225 起 | 用途 |
|---|---|---|---|
| `nominal` | 名义参数 | 名义参数 | 精确模型诊断，包含公开周期扰动 |
| `constant_delay_6` | 延迟 6 步 | 延迟 6 步 | 0.12 s 未建模延迟 |
| `constant_delay_15` | 延迟 15 步 | 延迟 15 步 | 0.30 s 未建模延迟 |
| `constant_delay_30` | 延迟 30 步 | 延迟 30 步 | 0.60 s 未建模延迟 |
| `delay_jump_0_to_30_at225` | 延迟 0 步 | 延迟 30 步 | 已形成控制权限后的延迟变化 |
| `gain_drop_1_to_0.25_at225` | 增益 `(1, 1)` | 增益 `(0.25, 0.25)` | 执行器作用减弱 |
| `gain_jump_1_to_4_at225` | 增益 `(1, 1)` | 增益 `(4, 4)` | 执行器作用增强 |
| `inertia_jump_x4_at225` | 惯量 `(0.8, 1.0)` | 惯量 `(3.2, 4.0)` | 负载/惯量变化 |

除表中指定参数，其他仿真参数不变。常值延迟从第一步生效。突变场景不重置身体状态、门控计数、上一步命令或命令历史。首版协议对四个突变场景使用了简名，实施前仅将名称对齐到代码和报告的完整标识；参数、种子、窗口及预算没有变化。

每个场景、每个种子运行下列 6 个方法：

| 方法 | 动作生成 | 权限规则 |
|---|---|---|
| `zero` | 零命令 | 最高档位，用作无主动控制参照 |
| `pd` | 固定 PD 与名义前馈 | 最高档位 |
| `full` | 固定模型候选规划 | 始终最高档位 |
| `fixed` | 同一固定模型候选规划 | 每 75 步固定开放一档 |
| `competence` | 同一固定模型候选规划 | 原能力门控 |
| `competence_sustained` | 同一固定模型候选规划 | 原门控加持续表现失败退级，显式启用 |

矩阵共 `8 × 3 × 6 = 144` 次运行，仿真步数上限 `144 × 450 = 64,800`。任何早停均保留，不补跑至同样成功，也不隐藏失败种子。实际执行步数和早停原因单独报告。短时域模型预测步数不计为真实环境交互，需与实际仿真推进区分。

## 4. 延迟与门控时序

令本轮当前控制步为 0-based `t`，当前场景延迟为 `d(t)`。控制器先读取 `state[t]` 并产生 `command[t]`，仿真器实际执行 `command[t - d(t)]`；若索引小于 0，执行零命令。周期扰动与执行器增益随后作用于同一次状态推进，产生 `state[t + 1]`。变更延迟时仍按完整历史命令索引取值，不用新建零队列掩盖变化。延迟突增会回读、重复已经执行过的旧命令；这是明确的历史索引时延抽象，不是对真实通信缓存队列的仿真。

`effective_torque = actuator_gain * applied_command`，周期扰动作为额外外部力矩另加。硬限额 `1.2` 约束控制命令，不对未知增益后的有效力矩重新夹紧；因此增益 4 场景可出现大于名义命令限额的实际控制作用。报告须分别记录发出命令、实际历史命令和增益后的有效力矩，避免夹紧隐瞒执行器失配。

门控只在当前动作执行后、完整证据窗口结束时观察证据，决定下一步及之后的权限。不能根据本步尚未产生的反馈提前改变本步动作。窗口不足时若先触发安全终止，记为状态退出及未满窗口，不能记为门控检测失败或一次门控退级。

退级后，延迟执行器可能继续执行退级前发出的高权限命令。记录必须分别保存当前发出命令、实际执行历史命令和当前权限。当前命令满足权限限额不等于延迟系统已撤回全部历史控制作用；历史高权限动作不能被误记为本步新命令违规，也不能从权限暴露记录中消失。

## 5. 持续表现失败退级变体

原门控完整保留，包括无效证据、状态不安全、预测失配、窗口最大残差过大引起的立即退级；最低档无法继续退级时记录保持及原因。

新变体只增加以下规则：在不存在上述立即处理条件时，若当前档位连续 3 个完整窗口不能满足原来的 competence 条件，即跟踪误差、峰值速度与恢复条件未同时通过，则撤回一级权限。成功窗口和任意退级都将连续失败计数清零；晋级也开始新的档位计数，不跨档累计失败证据。最低档连续失败仍记录检测事件，不能伪报为发生了退级。该规则不改变预测、跟踪、恢复等阈值，也不更换身体模型或 PD 增益。

变体改变的是权限状态机，不能称为学习算法。本批结果产生后不改为 2 个或 4 个失败窗口，不增加新场景强度追求一个有利结论。若需要后续修改，保留本批结果，以新的协议和独立批次报告。

## 6. 证据、指标与主要比较

所有关节状态可被观测；门控跟踪与恢复判断仍只针对当前档位活动关节。全目标指标始终计算两关节，含未开放关节。两者分别报告，防止只因关节未开放而看起来更容易满足“能力”。

预测残差使用既有定义：对位置按 `0.35 rad`、速度按 `1.2 rad/s` 归一化后，计算四维单步预测残差 RMSE。窗口预测 RMSE 为单步归一化残差平方的均值再开方；`model_error_bound` 字段是该窗口最大单步残差。它包含公开周期扰动影响，是无量纲的已观测残差，**不是经过校准的不确定性界或预测置信区间**。

主要报告内容为：

1. 全目标闭环跟踪 RMSE，单位 rad；全部已执行步、前 225 步和后 225 步分别计量。常值场景也按相同时间切分，但不称为突变前后收益。
2. 是否完成预算、实际步数、首次状态限位/非有限退出及其时间；出现早停时，后半段指标使用真实已执行步且披露样本数，完全未执行的阶段记为缺失，不填零。
3. 各档位暴露步数、活动关节步数、当前命令触及权限限额的步数、触及硬限额的步数、规划回退步数；迟到高权限命令的实际执行另报。
4. 每个完整门控窗口的证据、晋级/退级/保持原因，变体的连续失败计数，最后不足 25 步的证据数量。
5. 突变后的首次完整窗口失败检测与首次实际退级时间，分别给出距离 step 225 的步数和秒数。记录突变前最后应用档位、首次失败窗口的 `level_before` 及是否已在最低档。突变前的失败/退级不能作为突变响应；突变后未检测、最低档失败而无法退级或提前终止时明确标注。
6. 动作选择耗时、源代码与固定参数指纹、Python/NumPy/操作系统版本、设备 CPU、模型和策略参数更新次数 0。

主要比较在同场景、同种子内配对：`full` 对 `fixed`、原门控对持续失败变体。退级只能证明权限状态改变，不能默认记为收益。必须同时检查跟踪、状态退出与真实执行作用：变体若更多退级却不能改善控制，或长留低档使未开放关节误差增大，应作为不利结果完整报告。3 个种子只提供机制开发证据，不作普适统计优势结论。

## 7. 软件验收与结果保存

实施后先通过有意义的 CPU 测试，再运行冻结矩阵。测试覆盖固定和突变延迟的历史索引、参数突变不重置状态、原门控行为兼容、变体连续失败与清零、最低档保持、时序边界、早停和末尾不足窗口计量。测试可使用构造证据检验状态机；这些测试结果与真实闭环场景的退级结果分开报告。

一次完整交付至少包含：冻结协议、固定配置、源代码 commit/dirty 状态与文件校验值、逐运行报告、逐步轨迹、门控事件、实际交互总数、测试摘要和结果解释。运行前后校验模型及固定配置指纹一致。结果文件保留所有方法、场景和种子，采用有限数值或明确缺失值保存，不用 NaN 掩盖不可读报告。

验收标准是矩阵和证据完整、时序正确、无参数训练、能够复核结论；不以原门控或变体必须优于其他方法作为通过条件。若所有场景都未触及实际边界，如实写“本预先固定的压力范围尚未发现该类失效”，结束本批，后续扩展另开协议。

下一阶段只有在用户明确要求开展学习实验后才运行 CPU 在线辨识，并与同初始化的冻结模型比较。这一阶段保持当前“CPU、暂不训练”的授权范围。
