## 讨论一：如果换成 Isaac Lab 和 G1，论文效果是否会更好？

### 项目提出者

> 如果我们这里换成真实的 Isaac Gym，换成真实的机器人模型，比如 G1，通过这样的对比，我们论文的效果会不会很好？

### 研究助手

会明显提升论文说服力，但关键不只是“把火柴人换成 G1”，而是要在真实刚体动力学中做公平、完整的实验。

需要澄清：Isaac Gym / Isaac Lab 中的 G1 仍然是高保真仿真机器人，不是真实机器人。建议采用当前的 Isaac Lab 作为二维代理与真实 G1 之间的验证阶段。

论文证据层级可以理解为：

- 二维火柴人：证明想法能够运行，属于概念验证；
- Isaac Lab + G1 + 完整消融：形成可信的仿真人形机器人论文；
- 增加真实 G1 少量安全实验：显著提高论文说服力。

不能只比较“传统 PPO”和“完整发育式算法”，否则无法判断提升来自课程、人体数据还是 Body Schema。至少应比较直接 PPO、课程 PPO、人体先验 + PPO、Body Schema + PPO 和完整 DHP-PPO，并加入动作重定向 + 模仿 PPO 或 PBHC / DeepMimic 风格强基线。

G1 的发育课程可以设计为：

```text
关节安全探索
→ 双脚站立
→ 扰动下平衡
→ 左右重心转移
→ 单脚抬起
→ 单步运动
→ 向上辅助力行走
→ 逐渐降低辅助力
→ 完全无支撑行走
```

论文最重要的结论不应只是最终 Reward 更高，而应是在达到相同行走成功率时，发育式方法是否使用更少交互、发生更少严重跌倒，并能更快适应扰动和动力学变化。

## 讨论二：真实机器人从零发育的最终目标是否正确？

### 项目提出者

> 我的最终层级目标，是把一台真实的、完全没有经过训练的机器人放在环境中，通过自己学习翻身等一步步操作，最终学会站立。我的思路对吗？

### 研究助手

大方向正确，这正是发育式机器人学习的核心，但“完全没有经过训练”需要改成“没有预训练任务策略”。

真实机器人可以没有预训练的翻身、起身和站立策略，但必须具备：

- 关节、速度和力矩限制；
- 电流与温度保护；
- 碰撞检测和紧急停止；
- 软垫与安全吊架；
- 基础姿态、接触和本体感知；
- 低风险动作空间和独立安全控制器。

这些机制不是预先教会机器人站立，而是保证它能够安全学习。推荐的真实机器人研究目标是：

> 将一台没有预训练翻身、起身和站立策略的真实人形机器人放入安全环境，使其通过低风险身体探索建立 Body Schema，逐步学习身体方向识别、接触控制、翻身、姿态转换、辅助站立、平衡和独立站立。

建议发展顺序为：

```text
安全感知与关节校准
→ 低力矩 Body Babbling
→ 关节—身体响应学习
→ 地面接触和身体方向学习
→ 侧卧/俯卧/仰卧转换
→ 自主翻身与倒地恢复
→ 坐姿或跪姿稳定
→ 辅助起身
→ 逐渐减少辅助力
→ 独立站立
```

第一篇真实机器人论文建议先回答“能否以更少真实交互和更少严重失败，从随机倒地姿态学会自主恢复并独立站立”，而不是直接扩展到完整行走。

## 讨论三：能否模拟婴儿发育，逐步开放关节限制？

### 项目提出者

> 机器人可以没有任务策略，但必须预先具备安全机制。我们是不是可以模拟婴儿的发育过程，逐步放开关节限制？

### 研究助手

可以，而且这是很有研究价值的机制，可以称为人工运动成熟机制或发育式动作空间扩展。

需要区分：机械硬极限、电机最大安全力矩、速度、温度和碰撞限制永远不能解除；可以逐步扩大的，是控制权限、关节活动范围、参与控制的自由度、力矩、速度、动作频率、探索噪声和外部支撑。

动作空间可以表示为：

$$
\mathcal A_0\subset\mathcal A_1\subset\cdots\subset\mathcal A_{\text{full}}.
$$

策略动作经过关节掩码和阶段范围后执行：

$$
a_t^{\text{exec}}=m_k\odot\mathrm{clip}(a_t,-r_k,r_k),
$$

$$
\tau_t^{\text{exec}}=\alpha_k\tau_t^{\text{policy}}.
$$

不建议按照固定训练时间开放自由度，而应根据当前技能成功率、Body Model 预测误差、危险状态、力矩饱和、人工干预和扰动恢复能力决定是否解锁。如果风险升高，系统应回退到更安全的权限范围。

这个机制可以通过三种方案比较：

1. 从一开始开放完整动作空间；
2. 按固定时间开放动作空间；
3. 根据能力和风险自适应开放动作空间。

从而研究机器人是否能像生物运动系统一样，随着身体模型和控制能力成熟，逐步获得更大的运动自由度。

## 讨论四：机器人是否需要压力传感器，应该如何实现？

> **后续修订：** 本节最初提出的20～30个压力点不应被称为第一版最低配置。讨论六根据项目短期资源重新设计了零硬件改造架构。本节作为思想演进记录保留。

### 项目提出者

> 这里很重要的是机器人需要带有压力传感器，这个应该怎么做？

### 研究助手

压力和接触感知很重要，但如果目标包含翻身、坐起和起身，只在脚底安装压力传感器不够。机器人早期主要通过背部、手掌、膝盖、骨盆和身体侧面与地面接触。

推荐采用：

$$
\text{脚底精确测力}
+\text{手膝压力检测}
+\text{躯干分布式接触检测}
+\text{IMU和关节状态}.
$$

最低可行版本包括每只脚四个载荷点、每只手2～4个压力点、每侧膝盖1～2个压力点、背部约6个接触点和身体两侧各2个接触点。约20～30个测量点即可开始研究。

脚底四点载荷可以计算总垂直力和压力中心：

$$
F_z=\sum_iF_i,
$$

$$
CoP_x=\frac{\sum_iF_ix_i}{\sum_iF_i},\qquad
CoP_y=\frac{\sum_iF_iy_i}{\sum_iF_i}.
$$

手、膝和背部初期可以使用低成本 FSR 检测接触；脚底使用精度更好的应变式载荷单元；高精度版本再考虑踝部六维力传感器和柔性压力阵列。

压力原始数据需要转换为接触状态、总压力、压力中心、压力变化率、接触持续时间、新增/消失接触和左右承重差。碰撞与冲击保护必须由独立的高频控制器处理，不能完全交给神经网络。

## 讨论五：刚性机器人无法贴合人的真实学习感受，项目是否仍然成立？

### 项目提出者

> 但是机器人是一个刚性的物体，这里似乎怎么做都不能完美贴合人真正的学习感受。

### 研究助手

这一判断正确。刚性机器人不可能真正复制人的身体感受，也不应将项目表述为“让机器人获得和婴儿一样的感觉”。人体具有软组织、肌肉和肌腱弹性、连续触觉、疼痛和疲劳，而刚性机器人主要由连杆、电机和减速器组成。

项目不需要复制人体，而应提取功能原则：

| 人体能力 | 机器人抽象 |
|---|---|
| 皮肤触觉 | 压力和接触阵列 |
| 肌肉拉伸 | 关节位置和速度 |
| 肌腱受力 | 力矩传感器和电机电流 |
| 前庭感觉 | IMU |
| 肌肉弹性 | 阻抗和柔顺控制 |
| 疼痛 | 冲击、温度和力矩风险代价 |
| 反射 | 独立底层安全控制器 |
| 内部身体模型 | Body Schema / Forward Model |
| 身体成熟 | 动作空间和力矩权限逐渐扩大 |

工程上可以通过脚底、手掌、膝盖和背部软质保护层，柔顺脚底，力矩/阻抗控制，低刚度初期训练，软垫和安全吊架降低刚性接触问题。但这些仍然只是工程等价物，不是人的主观感受。

推荐的论文表述是：

> 本研究不复制人类的主观感觉和解剖发育，而是提取低风险探索、身体模型形成、渐进运动自由度、接触反馈和技能积累等发育原则，并研究这些原则能否提高刚性人形机器人的学习安全性与样本效率。

真正有价值的科学问题不是“机器人能否变成婴儿”，而是：

> 即使机器人与人体在材料、驱动和感知上存在巨大差异，人类运动发育中的哪些原则仍然能够迁移到刚性机器人？

## 讨论形成的共同结论

1. 项目的最终对象是真实人形机器人，但需要经过二维代理、G1刚体仿真和受保护真机实验逐级验证；
2. “从零”指没有预训练任务策略，而不是没有安全本能和底层控制；
3. 发育过程应按机器人结构重新设计，不机械复制婴儿姿势；
4. 逐步开放关节、力矩、速度和支撑权限可以形成独立的算法创新点；
5. 翻身和起身需要全身接触感知，不能只依赖脚底压力；
6. 刚性机器人不复制人的感觉，而抽象并验证人的发育学习原则；
7. 所有结论必须通过信息预算匹配、组件消融、强基线和真实安全指标进行验证。

## 讨论六：原压力传感架构短期不可行

### 项目提出者

> 但是这个是我短时间无法做到的，这个架构不合理，我不满意。

### 研究助手

这个批评成立。此前把脚底、手掌、膝盖、背部和身体侧面共20～30个压力点称为“第一版最低可行配置”，实际低估了机械改造、布线、采集同步、标定和耐久性工作的成本。

修订后的近期架构不改造 G1 硬件，只使用原生 IMU、关节编码器、电机电流/力矩估计、动作指令和跟踪误差。在 Isaac Lab 中使用真实接触标签作为教师，训练只依赖原生信号的学生接触估计器；部署到真实机器人时移除仿真特权信息。

近期真实实验只要求软垫、吊架或机械限位、急停、低力矩和少量固定初始姿态。外部 RGB-D 相机或地面测力板只作为评估真值，不是策略必需输入。

实施路线调整为：

```text
A：Isaac Lab G1纯软件MVP
→ B：G1原生传感器的受保护真机验证
→ C：有明确数据需求后再增加足底或全身触觉
```

压力鞋垫、踝部六维力传感器和电子皮肤属于后续增强研究，不再作为当前项目的启动条件。

## 讨论七：24 GB 显存新电脑上的实施计划

> **后续修订：** 本节保留当时针对一台特定电脑的讨论，但其中显存容量和并行环境数不应成为项目通用配置。讨论十将执行手册改为基于实测资源自适应。

### 项目提出者

> 如果你拥有一个24G显存的电脑之后，你在我这里的计划是什么？

### 研究助手

新电脑不会直接启动一个庞大的“婴儿全发育”训练，而是先完成可验证、可发表的 Isaac Lab G1 软件 MVP。执行顺序为：环境与驱动审计、固定官方依赖版本、建立唯一 G1 关节/刚体/action 映射、验证模型/限位/接触/执行器、训练 Direct PPO 站立基线，再增加固定运动成熟、能力门控运动成熟、Body Schema 和接触估计。

24 GB 显存优先用于 headless 并行仿真。建议使用64～128个环境调试训练流程，接触密集任务从512～1024个环境开始，根据实际显存峰值和吞吐调整；简单站立任务确认稳定后才尝试更高并行数。不同 seed 顺序运行，不能因 OOM 只缩小某一实验组的模型而破坏公平性。

第一篇 G1 论文应收敛到一个明确问题：能力门控的运动成熟机制能否在站起/站立任务中，以相同成功率减少交互、严重跌倒和危险动作。全身电子皮肤、无保护真机训练和完整翻身—行走流程不属于近期启动条件。

## 讨论八：可以从 PBHC 等官方项目取得机器人数据

### 项目提出者

> 这里的机器人的数据源头你可以从官网PBHC等等之类的项目当中直接获得。

### 研究助手

这个思路合理。复用 PBHC、NVIDIA Isaac Lab 和 Unitree 官方仓库，可以减少 G1 模型、动作重定向、模仿学习与部署基础设施的重复开发，把精力集中在发育式算法和公平实验上。

但“数据源”必须分为三类：

1. G1模型、关节参数和仿真配置是公共环境资产，可让所有方法共享；
2. PBHC/SMPL或重定向动作是额外人体先验，必须披露数据量、转换方法和许可证；
3. 预训练checkpoint已经包含任务知识，只能明确作为教师、初始化或强基线，不能使用后仍声称没有预训练任务策略。

PBHC README 标注 CC BY-NC 4.0，使用时要署名并遵守非商业限制。每个外部来源都应记录官方URL、精确commit/tag、license、checksum、转换步骤和使用实验组。为保证论文结论清晰，项目设立两条分开的实验轨：不使用预训练任务策略的Pure developmental轨，以及明确使用PBHC/动作教师的Human-prior轨。

完整的来源表、公平比较规则和许可边界已经整理到 `docs/DATA_SOURCES.md`；新电脑接管顺序整理到 `docs/NEW_MACHINE_BOOTSTRAP.md`。

## 讨论十：交接文档不应硬编码特定数据和硬件

### 项目提出者

> 这里不需要强制指定这些数据。你这么写就太不通用了，显得很刻意。

### 研究助手

这个意见正确。此前把24 GB显存、固定并行环境数、PBHC和一组具体来源直接写进接管主路径，会让一次对话中的条件看起来像项目永久约束，也会降低文档在不同电脑、仿真版本和研究阶段中的可用性。

修订后的原则是：

1. `AGENTS.md`只固定项目使命、科学边界、当前研究目标和验收标准；
2. 新环境手册先探测实际软硬件，再通过短基准测试选择并行度，不预设显存容量或环境数量；
3. 新会话只强制阅读最小上下文，其余研究文档按任务加载；
4. 外部项目只作为候选示例，实际采用后才进入来源清单和数据预算；
5. 真正强制的是许可合规、来源可追踪、额外信息披露和实验公平，而不是指定某个数据集或仓库。

这样既保留了“新会话能够直接接管”的作用，也避免把特定机器和候选资源写成刻意的固定答案。

## 讨论十一：从生物发育重新明确在线学习目标

> 日期：2026-10-10。以下为本次讨论的含义整理，算法候选与推进步骤仍需实验验证。

### 项目提出者的核心问题与目标

动物出生后的快速运动发展，以及婴儿探索肢体时身体与控制能力的共同变化，对机器人算法有什么参考？项目希望模仿真实动物和人类的高效学习，使机器人减少对强化学习训练的依赖，能够在真实环境中通过少量交互逐步获得运动能力。

### 生物机制与工程解释

活动和负荷会参与肌肉、骨骼与神经系统的发育；运动改善还依赖身体自然生长、神经成熟、感觉整合和已有力量的协调。动物的快速起步包含遗传、产前发育及初始身体条件，出生后的时间不能被视为全部学习成本。

刚性机器人的电机不会通过练习生长。本项目提取身体校准、协调学习、能力门控和技能复用等功能原则；动作与力矩权限扩大是工程抽象，不能当作肌肉生长或技能提高的证据。

### 当前路线调整

1. 研究目标以少量真实交互中的能力获得和适应为中心；算法分类本身不是成效指标。
2. 优先验证自监督在线身体模型、受约束探索和局部预测控制；PPO 保留为对照。
3. 身体模型应直接参与控制决策，先检验预测改善能否转化为闭环收益。
4. 初始控制器、标称物理模型、默认姿态、支撑和运动基元全部披露；纯发育轨不使用预训练任务策略。
5. 冷启动学习与已有技能的适应分别报告。若学习前系统已经站稳，载荷或延迟变化后的收益属于适应，不称为从零学会站立。

### 项目推进顺序

先固定协议并修正二维基线的实现与溯源问题，建立独立 CPU 低维身体模型/控制原型；比较经典辨识、冻结模型与在线模型，再检验固定成熟、能力门控和探索机制。同步远端后确认已有 PBHC/Isaac Gym G1 来源、映射与 smoke 记录，应复用这些接口；恢复兼容 GPU 环境后复核变更部分，扩展到固定接触的受支撑站立和小幅重心控制。Isaac Lab 仅作为可选迁移。

仿真阶段检验机制、失效行为与共同任务条件。真实操作在明确授权及独立安全条件具备后开始，先做受保护的小幅探索与局部适应。减少支撑、接触切换、翻身、起身和行走按前一阶段验收结果逐级扩展。

该路线已整理到 [项目推进路线](DEVELOPMENT_ROADMAP.md)，并同步更新 `AGENTS.md`、README、新环境接管说明和研究愿景；本节记录研究设计，CPU 机制验证另见讨论十二。

## 讨论十二：CPU 验证范围与中间进度同步

> 日期：2026-10-10。

项目提出者要求当前仅使用 CPU、暂不训练，先验证算法机制，并要求开发过程中的中间进度提交、推送到仓库。

本轮因此只运行固定模型闭环仿真、动作权限/能力门控状态机与 CPU 测试，没有参数学习。45 个机制运行及各自的统一权限评估共执行 14,625 个仿真步；只能支持组件可运行，尚不能证明在线学习效率或门控降低风险。完整结果和原始记录见 [CPU 无训练验证](CPU_VALIDATION.md)。

推送准备时发现远端已有 PBHC + Isaac Gym G1 工程与地面发育进展，已正常同步并保留，修正本地旧文档的状态。历史 GPU 结果不算作本轮复现，原始 CPU 运行的 Git 元数据不改写。此后按可验证里程碑提交并推送，代码、实验原始指标、失败记录和结论边界一并保存；当前检查点见 [开发进度](PROGRESS.md)。
