# 真实机器人发育式运动学习：研究愿景与系统设计

> 文档状态：研究路线设计稿  
> 最后更新：2026-10-10
> 适用范围：从理想二维概念验证，经现有 PBHC + Isaac Gym / G1 仿真，逐步走向真实人形机器人自主翻身、起身与站立；Isaac Lab 是未来可选迁移后端

阶段执行以 [项目推进路线](DEVELOPMENT_ROADMAP.md) 为准。当前用户要求仅使用 CPU、暂不训练；本轮固定模型控制和门控验证没有更新模型或策略。下文中的长期技能序列不构成第一版必须同时实现的任务清单。

仓库已有另一台 GPU 主机上的 PBHC/G1 历史证据：映射、执行器与接触审计，以及冻结近站立工程评估；地面学习轨已通过身体模型阶段和翻身/支撑门，辅助起身在 0.32 m 前沿平台，持续起身与独立站立尚未验收。较强辅助和局部能力链失败分支均保留；这些仍是单 seed 方法开发，不是组间效率优势。本轮未复现历史 GPU 结果，依据见 [PBHC 接入记录](PBHC_INTEGRATION.md)及[实验日志](EXPERIMENT_LOG.md)。

## 1. 最终研究目标

项目的长期目标不是训练一个只能执行固定动作的策略，而是研究：

> 能否将一台没有预训练翻身、起身和站立任务策略的真实人形机器人放入安全环境，使其通过受约束的自主探索建立 Body Schema，逐步学习身体方向识别、接触控制、翻身、姿态转换、辅助起身、平衡和独立站立？

推荐使用以下公式概括：

$$
\boxed{
\text{No Pretrained Task Policy}
+\text{Safe Self-Exploration}
+\text{Body Model}
+\text{Skill Accumulation}
}
$$

这里的“没有预训练任务策略”不等于机器人没有任何安全机制、传感器校准或底层控制。真实机器人必须先具备安全本能，才允许进行真实环境学习。

### 1.1 当前算法方向

项目希望减少对海量仿真采样、复杂奖励和长时间任务策略训练的依赖。优先检验自监督在线身体建模、受约束探索、局部预测控制和能力门控；PPO 作为比较基线。仿真用于验证模型、算法机制及失效行为，真实环境中的少量学习是长期目标。

这一候选路线与已有 G1 的 Developmental PPO 开发轨分别计量。既有 Body Schema 辅助头和能力门控不能直接证明在线系统辨识与预测控制的净收益；现有资产、观测/动作接口、风险日志、冻结评估和录制工具可以复用。CPU 阶段先读配置、检查接口和冻结数据，无需启动 GPU 或训练入口。

生物的活动、身体生长与神经控制存在共同发育。刚性机器人可借鉴身体校准、协调学习、权限扩展与技能复用；电机不会因练习获得肌肉式生长。动物出生后的快速运动表现还依赖遗传、产前发育与初始身体条件，不能据此承诺机器人半小时从随机动作学会行走。

所有初始控制器、标称模型、默认姿态与运动基元均应披露。候选方法必须先证明在线更新对闭环控制的净收益；若收益只发生在未知载荷或延迟下，结论应限定为适应能力提升。

## 2. 项目的科学边界

### 2.1 不复制人的主观感觉

刚性机器人不可能真正获得婴儿的身体感受：

- 人体具有皮肤、脂肪、软组织和连续分布的触觉感受器；
- 肌肉和肌腱具有弹性，并能感受拉伸、疲劳和疼痛；
- 婴儿的力量、骨骼和神经系统会随时间共同发育；
- G1 等机器人由刚性连杆、电机和减速器组成，接触更局部、冲击更突然。

机器人测量的是传感信号，不具有人类的主观体验。因此本项目不应宣称“复制婴儿感觉”，而应研究功能层面的发育原则。

### 2.2 从生物机制到机器人抽象

| 人体机制 | 机器人中的工程对应 |
|---|---|
| 皮肤触觉 | 压力传感器和分布式接触阵列 |
| 肌肉拉伸感 | 关节角度和关节速度 |
| 肌腱受力感 | 关节力矩传感器和电机电流 |
| 前庭系统 | IMU |
| 肌肉弹性 | 力矩控制、阻抗控制和柔顺控制 |
| 疼痛 | 冲击、温度、力矩和碰撞等安全代价 |
| 反射 | 独立于学习策略的底层安全控制器 |
| 小脑内部模型 | Body Schema / Forward Model |
| 身体成熟 | 逐步扩大关节、动作、速度和力矩权限 |
| 技能发育 | 简单技能向复杂技能持续迁移 |

项目研究的核心映射为：

$$
\boxed{
\text{Biological Principle}
\rightarrow
\text{Robotic Abstraction}
\rightarrow
\text{Engineering Validation}
}
$$

## 3. 总体系统架构

```text
Native Joint / IMU / Motor Current Signals
             + Optional Contact Sensors
                         │
                         ▼
               Multimodal Body State
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
       Body Schema            Risk Estimator
       Forward Model          Pre-Failure Signal
              │                     │
              └──────────┬──────────┘
                         ▼
        Local Planner / Feedback Controller
                         │
                         ▼
        Motor Maturation / Safety Envelope
                         │
                         ▼
       Impedance Controller + Safety Reflex
                         │
                         ▼
                     Robot Body
```

学习策略不能直接覆盖硬件安全控制器。关节极限、过流、过温、碰撞、急停和吊架保护必须在独立的高频控制层执行。

身体模型在独立更新周期内学习，控制层使用经过检查的模型版本。模型不可靠、接触模式变化或规划超时时，应拒绝扩大权限并执行经过验证的回退行为。局部预测模型和约束规划不自动构成安全保证。

## 4. 发育式动作空间扩展

### 4.1 核心思想

机器人最初只能使用很小、很安全的动作空间，随着身体模型、当前技能和风险控制能力成熟，逐步获得更大的运动自由度：

$$
\mathcal A_0
\subset
\mathcal A_1
\subset
\cdots
\subset
\mathcal A_{\text{full}}.
$$

这一机制可以称为：

- **Artificial Motor Maturation，人工运动成熟机制**；
- **Developmental Action-Space Expansion，发育式动作空间扩展**。

### 4.2 永远不能解除的限制

- 机械关节硬极限；
- 最大安全电流和力矩；
- 最大安全速度；
- 电机温度限制；
- 碰撞、线缆和电池保护；
- 紧急停止条件。

### 4.3 可以逐步扩大的权限

- 参与控制的关节数量；
- 关节目标位置范围；
- 力矩和速度上限；
- 动作变化频率；
- 探索噪声强度；
- 允许的接触方式；
- 外部支撑和吊架辅助比例。

策略输出的动作经过当前阶段掩码和安全范围后才能执行：

$$
a_t^{\text{exec}}
=m_k\odot\mathrm{clip}(a_t,-r_k,r_k),
$$

$$
\tau_t^{\text{exec}}=\alpha_k\tau_t^{\text{policy}},
\qquad0<\alpha_k\le1.
$$

其中 $m_k$ 是开放关节掩码，$r_k$ 是动作范围，$\alpha_k$ 是当前阶段力矩成熟系数。策略必须观测这些条件，避免权限变化时发生策略混乱。

### 4.4 能力门控，而不是固定时间解锁

不应简单规定“训练两小时后开放膝关节”。建议定义成熟度：

$$
M_k=
w_1\cdot\text{Success}
-w_2\cdot\text{Risk}
-w_3\cdot\text{Prediction Error}
-w_4\cdot\text{Intervention}.
$$

只有当以下条件持续满足时才扩大权限：

- 当前技能成功率高于阈值；
- Body Model 预测误差低于阈值；
- 冲击、力矩饱和和危险状态低于阈值；
- 连续若干回合无需人工干预；
- 能从规定的小扰动中恢复。

如果风险突然升高，系统应降低动作权限或退回上一个安全阶段。

## 5. 从倒地到独立站立的发育顺序

不机械复刻婴儿动作，而是根据机器人形态选择可迁移技能：

```text
Safety Calibration
        ↓
Low-torque Body Babbling
        ↓
Contact and Orientation Learning
        ↓
Supine / Side / Prone Transition
        ↓
Self-righting and Ground Recovery
        ↓
Sitting / Kneeling Stability
        ↓
Supported Rising
        ↓
Supported Standing
        ↓
Independent Balance and Standing
```

### G1 长期设计示例

下表是设计示例，阶段编号不对应已经实现的 PBHC 地面轨。现有地面轨的 stage 0/1 为身体模型与翻身/支撑，stage 2 为辅助起身，后续才是蹲姿/直立和零辅助站立；以 [G1 方法](DEVELOPMENTAL_G1_METHOD.md)与冻结日志中的实际配置为准。

| 阶段 | 主要开放能力 | 主要保护 |
|---|---|---|
| 0：安全探索 | 少量腰、肩、髋关节 | 软垫、低力矩、低速度 |
| 1：身体摆动 | 腰、肩、髋协同 | 躺姿和吊架 |
| 2：翻身 | 增加膝、肘和躯干自由度 | 冲击限制和接触保护 |
| 3：坐起/跪起 | 扩大髋膝活动范围 | 外部支撑和限位 |
| 4：辅助起身 | 增加腿部承重力矩 | 吊架承担部分重量 |
| 5：辅助站立 | 开放踝关节和平衡动作 | 逐步减少辅助力 |
| 6：独立站立 | 接近完整动作空间 | 只保留硬件安全边界 |

是否学习爬行、跪起或特定翻身方式应由机器人结构决定。对人类有用的发育动作不一定适合刚性 G1。

## 6. 近期可行的接触感知架构

### 6.1 架构修订：压力传感器不是项目启动条件

早期版本曾将脚、手、膝、背部和身体侧面的20～30个压力点描述为“第一版最低可行配置”。这个判断不合理：它需要机械改造、传感器选型、布线、同步采集、标定和耐久性验证，短期工作量可能超过学习算法本身。

近期研究必须以**不改造 G1 机器人硬件**为约束。压力鞋垫、踝部六维力传感器和全身触觉皮肤全部降为后续可选升级，而不是第一阶段依赖项。

### 6.2 零硬件改造的原生信号

第一阶段只使用机器人通常已经能够提供或估计的状态：

| 原生信号 | 可获得的信息 |
|---|---|
| 关节位置与速度 | 身体构型、动作响应和运动学姿态 |
| 电机电流或关节力矩估计 | 异常阻力、碰撞和承重变化 |
| 机身 IMU | 重力方向、角速度、倾倒和翻滚趋势 |
| 控制指令与跟踪误差 | 执行器是否受到外部约束 |
| 已知机器人运动学模型 | 各连杆相对位置和距地高度估计 |

部署时的观测为：

$$
o_t=[q_t,\dot q_t,\hat\tau_t,\mathrm{IMU}_t,a_{t-1},e_t^{\text{track}}].
$$

这套观测不要求新增压力传感器。它不能精确测量每个接触点的压力，但足以启动“姿态识别、异常受力、是否发生接触”的估计研究。

### 6.3 用仿真接触标签训练真实部署估计器

现有 Isaac Gym 可提供各刚体净接触力，但启用自碰撞时它不标识接触对方，不能把非足净接触力直接解释为地面接触。后续接触估计应先验证接触标签语义，必要时使用经过审计的几何过滤或能提供接触对的后端；Isaac Lab 是可选迁移方案。未来训练阶段可让教师读取有效的特权接触标签，学生只能读取将来真实机器人可用的原生信号；当前 CPU 无训练阶段不拟合该估计器：

```text
Validated simulator contact labels ────────► Teacher target
                                                     │
Joint + IMU + torque history ─────► Contact Estimator│
                                                     ▼
                                   Body-part contact probability
```

定义第 $i$ 个身体部位的接触标签 $c_{i,t}^{*}$，学生估计：

$$
\hat c_{i,t}=g_\phi(o_{t-H:t}),
$$

并使用二元交叉熵训练：

$$
\mathcal L_{contact}
=-\sum_i\left[
c_{i,t}^{*}\log\hat c_{i,t}
+(1-c_{i,t}^{*})\log(1-\hat c_{i,t})
\right].
$$

使用一段时间历史而不是单帧，可以利用电机电流突变、关节停止、IMU冲击和指令跟踪误差共同判断接触。部署时移除教师和仿真标签，只保留学生估计器。

这是**特权学习 / Teacher–Student Distillation**，它把接触传感器问题先转化为可验证的软件问题。

### 6.4 近期真实机器人实验边界

短期真机实验不要求机器人面对任意未知环境自主发育。建议先限制为：

- 已知、平整且有软垫的地面；
- 人工设置少量固定初始姿态，例如仰卧、左侧卧和右侧卧；
- 低力矩、低速度和有限关节范围；
- 吊架或机械限位只负责防止二次冲击；
- 独立急停和人工监护；
- 先离线记录原生信号，再进行低风险闭环控制。

可选使用一个固定 RGB-D 相机提供姿态真值，用于评估接触估计器，而不是作为最终策略的必需输入。也可以使用地面测力板做实验评估，避免改造机器人本体。

### 6.5 三层实施路线

| 层级 | 时间定位 | 硬件要求 | 要验证的问题 |
|---|---|---|---|
| A：纯软件机制验证 | 当前及后续 | CPU 局部原型；复用 PBHC/Isaac Gym G1，无新增硬件，按需迁移 Isaac Lab | 先无训练检查，再经授权评价在线建模、控制、门控与必要接触估计 |
| B：原生传感真机验证 | 中期 | G1原生IMU/关节/电流，软垫、吊架、急停 | 仿真训练的接触估计与低风险技能能否迁移 |
| C：增强触觉研究 | 长期 | 可选足底测力、手膝压力、电子皮肤 | 分布式触觉能否进一步提高泛化和安全性 |

项目先复用 A 中已完成的资产与工程验证，再验证新增在线模型候选，不重做已有 G1 底座。只有仿真及离线证据支持、用户明确授权且现场安全条件具备时才进入 B；数据证明原生传感器无法区分关键状态后，再考虑额外传感器。

### 6.6 后续最小硬件升级

如果原生信号确实不足，第一项升级不应是全身20～30点触觉，而应从以下方案二选一：

1. **机器人外部测力板**：不改机器人，可获得总地面反力，适合实验标定；
2. **可拆卸压力鞋垫**：只改脚底附件，适合站立平衡和压力中心估计。

每只脚四点测力时，可计算：

$$
F_z=\sum_iF_i,
\qquad
CoP_x=\frac{\sum_iF_ix_i}{\sum_iF_i},
\qquad
CoP_y=\frac{\sum_iF_iy_i}{\sum_iF_i}.
$$

手掌、膝盖、背部和身体侧面的触觉只属于长期研究，不应阻塞当前算法和仿真实验。

### 6.7 近期能够与不能够声称的结论

零硬件架构可以验证：

- 原生信号能否估计粗粒度身体接触；
- 发育式动作空间是否减少仿真和受保护真机中的危险动作；
- Body Schema 是否提高姿态转换和技能迁移效率。

它不能声称：

- 已经获得精确的全身压力分布；
- 能在任意未知地面可靠识别所有接触；
- 已经实现无需监护的真实世界自主发育。

## 7. 刚性机器人如何获得工程柔顺性

机器人不能变成人体，但可以降低刚性接触带来的差异：

- 在脚底、手掌、膝盖和背部增加可更换的弹性保护层；
- 使用力矩控制、阻抗控制或柔顺控制；
- 初期降低关节刚度和运动速度；
- 使用柔顺脚底、软垫和安全吊架；
- 根据接触状态动态调整关节阻尼。

阻抗控制示意：

$$
\tau=K_p(q_d-q)+K_d(\dot q_d-\dot q).
$$

控制增益与力矩权限应按任务承重需求验证；过低的刚度或力矩可能使站立本身不可行。可在受保护且任务可行的范围内调整柔顺性，再按实测能力扩大权限。这是对张力调节和能力开放的工程抽象，不能称为机器人肌肉生长。

## 8. 复用 PBHC/G1 的验证路线

当前 G1 实现基于 PBHC + Isaac Gym Preview 4，已记录上游 commit、来源和资产校验值，验证了 23 个 action/非固定关节和 24 个折叠刚体的映射。现有 `src/developmental_g1/`、Hydra overlay、静态检查、冻结 evaluation-only 和录制工具是可复用底座。Isaac Lab 或其他后端仅在有明确需求时迁移，并重验对应接触、控制和 reset 语义。

历史近站立 checkpoint 的冻结评估支持工程可用性；从地面开始的随机策略发育轨支持翻身/支撑门通过，尚未持续起身。二者均不能替代共同任务、预算、多 seed 的正式方法对比。当前 CPU 阶段只接管这些记录及接口，不重新运行历史训练或 GPU 仿真，也没有真机结果。

### 8.1 当前机制实验与比较组

| 比较 | 要识别的贡献 |
|---|---|
| 经典反馈、简单系统辨识/预测控制 | 通用控制与已有模型提供了多少初始能力 |
| 相同初始化的冻结模型与在线模型 | 真实交互中的更新是否改善闭环控制 |
| 完整权限、固定成熟、能力门控 | 能力门控是否减少达到统一成功标准的交互和风险 |
| 受约束随机探索与主动探索 | 数据选择是否提高辨识和控制效率 |
| Direct PPO 与适用的强基线 | 与任务策略训练路线比较总体成本与性能 |

按阶段实现这些组，不把完整矩阵作为最小 CPU 原型的前置条件。当前先固定模型验证，用户明确要求开展学习后再比较冻结与更新。原有二维 Curriculum / Body Schema / Human Prior 因子消融、G1 Developmental PPO 地面开发和新在线控制路线分别报告；人体动作重定向、模仿策略或预训练 checkpoint 放入人体先验轨，实际选用后确认来源与许可。

### 8.2 评价指标

- 达到固定成功率所需 Environment Steps；
- 训练期严重跌倒和高冲击次数；
- 人工/仿真复位次数；
- 无支撑翻身、起身和站立成功率；
- 速度、姿态和动作跟踪误差；
- 足底冲击和力矩饱和；
- 关节限位和硬件风险；
- 能耗与 Cost of Transport；
- 推扰恢复能力；
- 摩擦、质量、负载和传感噪声下的泛化。

必须分别报告环境交互、人体先验样本和计算资源，不能将额外数据带来的优势表述为纯强化学习样本效率。在线学习还应报告学习前表现、校准与适应预算、支撑量、权限轨迹、模型更新与规划延迟；冷启动技能获得和已有技能适应分别评价。

## 9. 第一篇真实机器人论文的合理范围

第一阶段真机验证从固定接触模式与受支撑站姿开始。近期问题为：

> 没有预训练站立策略的机器人，能否通过有限的受保护探索建立身体模型，并在未见载荷、执行器响应或延迟变化下，以较少交互改善重心控制和站立稳定性？

若学习前的底层控制器已经能够站立，第一项结论应是在线适应，不能称为从零学会站立。进一步减少支撑、增加姿态变化与接触切换，应在本阶段验收后单独开展。

长期技能扩展保留为：

```text
Body Babbling
→ Contact Learning
→ Orientation Control
→ Self-righting
→ Supported Rising
→ Balance
→ Independent Standing
```

近期主要指标包括统一成功标准下的交互量、任务误差、扰动恢复、保护干预、支撑量与规划实时性；长期再增加倒地恢复和新姿态泛化。真实机器人操作须获得用户明确授权且现场安全条件具备。

## 10. 推荐的论文表述

中文：

> 本研究不复制人类的主观感觉和解剖发育，而是提取低风险探索、身体模型形成、渐进运动自由度、接触反馈和技能积累等发育原则，并研究这些原则能否提高刚性人形机器人的学习安全性与样本效率。

英文：

> We do not aim to reproduce human subjective sensation or biological development. Instead, we investigate whether functional principles of motor development can improve safe and sample-efficient learning in rigid humanoid robots.

## 11. 最终判断

项目的正确方向不是“把机器人变成婴儿”，而是回答：

> 即使机器人与人体在材料、驱动和感知上存在巨大差异，人类运动发育中的哪些功能原则仍然能够迁移到刚性人形机器人？

这使项目从对婴儿动作的表面模仿，提升为对发育学习机制可迁移性的工程研究。
