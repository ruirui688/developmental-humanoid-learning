# CPU 发育式学习：持续目标

更新：2026-10-12。**目标 active，持续推进到四项初期验收完成。** 每个里程碑检查、提交、推送后立即继续；不等待再次“继续”。用户明确暂停时才暂停，单个报告、局部成功或一次失败不能结束目标。

我们要验证：**机器人能否通过自身动作与感觉，用少量 CPU 身体辨识形成有用的身体模型，并通过预测控制和能力门控获得运动能力。** 先完成低维多关节验证，再扩展到全身站立与行走。

## 四项验收与推进顺序

| 阶段 | 必须验证的能力 | 完成条件 |
|---|---|---|
| **C4：当前** | 身体模型帮助双关节完整接触控制 | 至少两关节；一步/多步预测与完整闭环；同初始化、目标和权限的冻结模型/学习模型/调优 PD 对照；按事前预测、20% 模型贡献、5% 强 PD 与 1.05 实际努力门判断，并在自由躯干接触域和新留出复核 |
| **C5：C4 后** | 少量更新适应未知动力学 | 至少两类未见变化；冻结/适应对照；完整报告恢复交互、预测、控制、努力和失败，冷启动与变化适应分开计账 |
| **C6：C5 后** | 能力门控优于或区别于固定成熟 | 相同最终任务、权限和完成标准；公开探索/校准、晋退级、停滞、风险和努力，避免永久小动作替代完成任务 |
| **C7：最后** | 综合结论可复核 | 未参与开发的新 seed/条件、强基线与必要消融；全部失败、实际成本、配置、源码提交和逐 seed 原件；检查、提交、推送完成 |

完整轨迹与工程资格是科学评价的前置条件；停止轨迹不作部分排名。各实验的精确门在结果前冻结，本页不修改旧门。完整实验与证明算法优势分开报告；不通过就公开并继续有依据的有限修订，不能通过放宽门或补跑取得成功。

## 执行约束

仅 CPU、少量在线/离线身体辨识；不使用大规模 PPO、任务教师、预训练任务策略、GPU 训练或真机。身体结构、关节限位、任务目标、经典 PD、固定支撑和理想感觉公开为初始先验；接触力与真实动力学只作诊断，不能暗中进入部署模型。

每轮执行：**有依据的有限设计 → 冻结代码/协议并提交推送 → 首次执行 → 保存全部结果与失败 → 必要检查、结果提交推送 → 继续最早未验收项。** 不机械重跑旧实验或旧审计，不在同一失败上无限追加候选。遇到依赖时明确记录并继续独立工作。

长期全身翻身、起身、站立、行走及真机另需对应验证，CPU 局部成果不能代替。[详细阶段账本](CONTINUOUS_EXECUTION_PLAN.md)保留历史失败与费用，[项目路线](DEVELOPMENT_ROADMAP.md)保留长期目标。
