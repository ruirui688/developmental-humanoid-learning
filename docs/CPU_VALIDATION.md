# CPU 无训练验证与后续轻量学习方法

> 日期：2026-10-10。
> 当前约束：只使用 CPU，暂不训练策略或身体模型。
> 本次验证是固定模型控制与门控逻辑的工程检查，尚不是学习效率实验。

## 1. CPU 上优先采用什么方法

大规模 GPU 并行训练不是局部身体建模的必要条件。先降低控制维度、缩短预测时域，再根据简单方法的失效情况决定是否增加模型复杂度。

| 优先级 | 方法 | 在项目中的作用 | CPU 特点与限制 |
|---|---|---|---|
| 1 | 递推最小二乘 RLS / 带动作历史的 ARX | 在线辨识局部关节响应与延迟影响 | 小矩阵更新，无反向传播；需要有效激励与可辨识性 |
| 2 | 局部线性或标称模型的残差辨识 | 修正执行器响应、负载和阻尼偏差 | 参数少、可审计；有效范围通常局限于姿态和接触模式附近 |
| 控制配套 | 短时域预测控制 / 小范围候选动作规划 | 用预测结果选择当前动作 | 可以用 CPU；规划属于动作计算，不能算作模型学习 |
| 后续补充 | 小型非线性残差模型或小 MLP | 处理简单模型无法解释的系统误差 | 小数据和低维状态可以在 CPU 上拟合；需证明相比简单辨识的净收益 |
| 后续物理验证 | 小规模 CPU 刚体任务 | 检验重力、接触与执行器机制 | 可评估官方 MuJoCo 等候选；本轮没有安装或引入这些依赖 |

RLS、最小二乘拟合、在线参数辨识和小网络更新都属于学习。当前没有运行这些方法；表中是后续获得学习实验任务后采用的顺序。大动作空间、接触切换与完整 G1 全身控制的可行性不能由小关节结果推断。

## 2. 本次实现了哪些验证组件

代码位于独立的 `src/developmental_control/`，仅使用 NumPy 和 Python 标准库，没有调用 PyTorch 训练、GPU 或 Isaac Lab。

- `joints.py`：两个受支撑弹簧阻尼关节，显式惯量、阻尼、刚度、关节耦合、执行器增益与命令延迟；位置和速度不做物理夹紧。
- `planning.py`：独立的固定标称模型，预测 20 步，每关节至多 7 个恒定力矩候选，只执行选中动作的第一步。
- `maturation.py`：关节掩码、阶段力矩权限、硬命令限幅，以及连续通过后晋级、风险/预测失配后退级的状态机。
- `validate.py`：固定协议、逐运行指标、逐步轨迹、门控证据、源码校验值与快照；不包含参数拟合路径。

关节系统在零控制下也会回到机械平衡位置。任务是跟踪小幅非零关节目标，不是人形机器人站立。控制器已有标称物理模型、目标轨迹和手设代价；这些是公开的初始知识。

门控改变当前权限，规划器每步重新选择动作；身体模型、PD 增益、规划配置和门控阈值始终固定。运行前后用参数指纹检查一致性。

动作合法与状态安全分开统计。有限状态超限会结束运行并记录原因；非有限异常保留对应运行，未知指标记为 `null`。零力矩回退仅适用于这个受支撑稳定夹具，不能视为真实人形机器人的安全动作。

## 3. 固定协议

| 项目 | 设置 |
|---|---|
| 随机初态 | seed 0、1、2；各方法共享相同初态生成规则 |
| 真实动力学场景 | 标称匹配诊断、惯量加倍、未建模的 6 步延迟 |
| 观测与目标 | 关节角度和角速度；统一目标为 0.08、−0.06 rad |
| 时步 | 0.02 s；6 步延迟对应 0.12 s |
| 机制阶段 | 每运行 225 个控制步；记录权限轨迹与全关节误差 |
| 统一评估 | 每运行 100 步，从独立且共享的初态重置，统一开放完整权限 |
| 小扰动 | 每 25 步的前两步施加固定外力矩，记录随后窗口的跟踪与速度恢复条件 |
| 方法 | 零控制、固定 PD、完整权限规划、固定进度规划、能力门控规划 |
| 初始权限 | 先开放一个关节，随后两个关节，再扩大力矩；完整配置写入报告 |
| 更新次数 | 身体模型 0 次，策略 0 次；没有递推辨识、监督拟合或自动调参 |

匹配标称参数的场景明确作为准确模型诊断条件。失配场景中规划器仍只读取标称模型与观测，不能查询真实 plant 来挑选动作。

门控的阶段证据只衡量当时开放的关节，但全关节误差始终报告，最终评估使用同一完整目标和权限。门控中的 `model_error_bound` 是窗口内观测残差最大值，尚不是经过校准的不确定性界。预测残差按位置/速度上限归一化，跟踪误差单位为 rad。

## 4. 本机实际结果

使用 Python 3.10.11、NumPy 1.26.4。最终版本的 45 个机制运行及其 45 个统一评估共执行 14,625 个仿真步，耗时约 13.14 s。该时间包括本地 NumPy 仿真和动作计算，与真实机器人交互时间不同。

模型与固定配置的前后指纹一致，模型参数和策略参数更新均为 0。运行时的本地测试为 **44 passed**，涵盖旧二维测试、新动力学/规划测试、门控与限幅、延迟队列、非有限异常保留和无训练审计。随后同步远端 PBHC/G1 工作，合并及末尾空白清理后的 CPU 回归检查为 **101 passed in 2.07 s**；没有重新运行历史 GPU 实验或启动参数学习。

统一权限评估的全关节轨迹 RMSE，以下为三个初态 seed 的平均值：

| 场景 | 零控制 | 固定 PD | 固定模型规划 |
|---|---:|---:|---:|
| 标称匹配诊断 | 0.067783 | 0.028016 | 0.025308 |
| 惯量失配 | 0.067834 | 0.033216 | 0.028787 |
| 未建模延迟 | 0.067783 | 0.031180 | 0.028344 |

这些数值只反映本协议中的固定控制表现，不能证明模型学习优势或总体样本效率。没有根据这批结果优化模型、控制增益或门控阈值。

- 三种规划模式在统一权限、重置初态后完全相同，这是模型和控制规则没有学习变化的预期结果。
- 九个能力门控机制运行均晋级两次，共 18 次晋级；实际仿真没有出现退级。
- 本批所有运行没有状态超限或非有限异常。夹具本身稳定且测试范围小，这不能证明真实安全性或门控降低风险。
- 风险与模型失配退级目前由合成证据单元测试验证；不能声称本批实际仿真已经识别了延迟失配或主动避免了危险。
- 各运行动作选择延迟的 95 分位值最高约 2.26 ms；计时不含证据汇总、门控、通信和硬件执行，不能据此承诺完整闭环实时性。

此次支持的结论是：固定模型控制、动作权限、门控状态机与日志能够在 CPU 上运行。在线身体学习、冷启动技能获得、技能保留/迁移、G1 站立和真机效果仍未验证。

## 5. 复现与原始文件

在仓库根目录执行：

```powershell
$env:PYTHONPATH = "src"
python -m pytest -q
python -m developmental_control.validate --output results/cpu_validation/final
```

可审计的原始结果已归档到 [2026-10-10 无训练验证](../results/cpu_validation/2026-10-10_no_training/README.md)：包含完整报告、门控事件、压缩的原始逐步轨迹、精确源码 ZIP 与文件校验清单。本机 `results/cpu_validation/final/` 同时保留未压缩输出和运行时源码副本：

- `report.json`：全部配置、逐 seed 指标、Git commit/dirty 状态、源文件校验值、环境版本及参数冻结审计。
- `trace.csv`：每步状态、动作、扰动、权限与预测/跟踪误差。
- `gate_events.json`：每个门控窗口的证据、晋级/退级原因与计数。
- `source_snapshot/developmental_control/`：对应运行的精确源码副本，可恢复未提交版本。

除明确的日期归档外，其他生成目录仍忽略，不覆盖已有 `results/validation/` 数据。原始运行的 Git 元数据保留为 `6abcf26` 加未提交改动；推送准备时同步到 `7363880`，没有把旧运行改写成新提交上的实验。提交前仅清理三个源文件末尾的空行，原始源码保留在 ZIP 中；清单分别记录原始与提交版本的源码校验值。具体时间关系与复核方法见归档说明。再次验证应指定新目录，以保留每次原始记录。
